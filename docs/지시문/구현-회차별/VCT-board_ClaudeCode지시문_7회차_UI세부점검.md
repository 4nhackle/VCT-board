# VCT-board 7회차 지시문 — 화면 세부 결함 점검과 개선

## 목적

기능은 다 되지만 보기에 거슬리거나 쓰기 불편한 작은 결함을 찾아 고친다. 출발점은 오른쪽 아래 고정 막대(`.dock`: "바로가기" 고르기 상자 + "↑" 맨 위로 버튼)다. 다크 모드 데스크톱에서 이 막대가 밝은 흰 테두리로 무겁게 떠 있고, 주변 컨트롤보다 크며, 아래 글을 가린다. 이와 같은 종류의 결함을 사이트 전체에서 찾아 같은 기준으로 고친다.

기준 문서는 `docs/디자인/design-brief.md`다. 장식보다 위계를 앞세우고, 토큰(`--fs-*`, `--sp-*`, `--r-*`, `--tap`, 색 변수)만 쓴다. 새 디자인 방향은 만들지 않는다.

## 0. 지킬 것

- `main` 최신에서 브랜치 `fix/ui-polish-7`을 만든다. `main`에 직접 커밋하지 않는다.
- 아래 파일·폴더는 건드리지 않는다. 예약 작업이 자동으로 커밋하는 곳이라 충돌을 피한다.
  - `data/`
  - `index.html`의 머리말 시각
  - `og.png`
  - `.github/`
- 바꾸는 범위는 `css/style.css`, `js/`의 화면 코드, `index.html`의 마크업이다. 주소, ID, 데이터 형식, 정렬 결과는 바꾸지 않는다.
- 단계마다 아래 세 명령이 모두 통과해야 한다.
  - `node scripts/test.mjs`
  - `node scripts/validate.mjs`
  - `node scripts/build.mjs _site`
- 먼저 점검만 하고 결과를 한 번 보고한 다음 고친다. 확인되지 않은 항목은 고치지 않고 "재현 안 됨"으로 기록한다.
- 디자인 판단이 갈리는 항목은 고치지 말고 선택지 두세 개와 추천을 적어 사용자 결정으로 넘긴다. 예를 들어 막대를 없앨지 말지 같은 것이다.

## 1. 점검 환경

`scripts/dev-server.mjs`로 띄운 `http://localhost:8080/VCT-board/`를 Playwright(Chromium)로 연다. 데이터가 적으면 `scripts/fixtures`의 샘플로 만든 사이트(`fixture-site.mjs`)도 함께 본다.

조합마다 스크린샷을 `/tmp/ui-audit/before/<화면>-<폭>-<모드>.png`로 남긴다.

- **폭**: 375(모바일), 768(태블릿), 1280(데스크톱), 1920
- **모드**: 라이트, 다크(`emulateMedia({ colorScheme })`). `prefers-reduced-motion: reduce`도 한 번 본다.
- **화면**:
  - 목록의 각 탭 맨 위
  - 600px 넘게 내린 중간
  - 맨 아래(푸터)
  - 검색 결과 0건
  - 인물 상세, 팀 상세, 없는 주소
  - 일정 탭, 건의 탭
- **키보드**: Tab으로 처음부터 끝까지 이동하며 초점이 보이는지, 순서가 자연스러운지 본다.
- **글자 크기**: 브라우저 확대 200%, 긴 이름과 긴 팀명이 들어간 행을 본다. 샘플 데이터에 일부러 긴 값을 넣는다.

## 2. 이미 찾은 후보 (먼저 재현하고, 맞으면 고친다)

코드를 읽고 찾은 것이라 실제 화면에서 확인해야 한다.

- **U-01 막대가 너무 무겁다**
  - 원인: `.dock select, .totop`의 테두리가 `1px solid var(--ink)`다. 다크 모드에서 `--ink`가 `#E9ECEA`라 흰 윤곽선이 된다.
  - 원인: 그림자 `rgba(0,0,0,.18)`는 다크 바탕에서 보이지 않는다.
  - 방향: 테두리를 `--line` 또는 `--mute` 수준으로 낮춘다. 바탕과 구분은 면색과 모드별 그림자로 한다. 다크 모드에서는 그림자 대신 살짝 밝은 면을 쓴다.
  - 확인: 라이트와 다크 둘 다 본문과 겹쳤을 때 막대가 읽히는지, 대비가 3:1 이상인지 본다.
- **U-02 막대 크기가 다른 컨트롤과 다르다**
  - `min-height: 44px`가 고정값이다. 데스크톱 `--tap`은 36px라 데스크톱에서만 막대가 탭·칩보다 크다.
  - 방향: `var(--tap)`으로 바꾼다. 모바일은 원래 44px라 그대로다.
- **U-03 푸터가 막대에 가려진다**
  - `.site-foot` 규칙이 css에 두 번 있다. 뒤 규칙의 `padding-bottom: 56px`이 앞의 `calc(44px + var(--sp-6))`을 덮는다.
  - 막대는 바닥에서 16px에 높이 44px라 60px을 차지한다. 그래서 푸터 마지막 줄이 막대 밑에 깔릴 수 있다.
  - 방향: 중복 규칙을 하나로 합친다. 아래 여백은 막대 높이와 위치를 담은 변수로 계산해 safe-area까지 반영한다.
  - 같은 방식으로 css 전체의 중복·충돌 선택자를 찾아 정리한다. 예: `.note-lfx`, `.doc .back`과 `.back`.
- **U-04 "↑"가 글자 하나다**
  - 글꼴에 따라 굵기와 세로 위치가 달라진다.
  - 방향: 인라인 SVG 화살표(`currentColor`, `aria-hidden`)로 바꾸고 버튼 가운데에 맞춘다. `aria-label="맨 위로"`는 유지한다.
- **U-05 바로가기 고르기 상자**
  - OS 기본 모양(화살표, 배경)이 모드마다 다르게 보인다. `max-width: 13rem`이라 데스크톱에서 길다.
  - 방향: `appearance: none`과 토큰 색 화살표로 맞추고, 폭은 내용에 맞게 줄인다.
  - 고른 뒤 `value = ""`로 되돌리는 동작은 유지한다.
  - 다크 모드에서 펼친 옵션 목록의 글자색과 바탕색이 읽히는지 확인한다.
- **U-06 바로가기로 이동한 위치**
  - 모바일에만 `.rh { scroll-margin-top: 44px }`가 있다. 데스크톱에서는 sticky 탭(약 45px) 밑으로 구역 머리가 들어갈 수 있다.
  - 확인: 각 폭에서 바로가기로 이동한 뒤 구역 제목이 탭 바로 아래에 온전히 보이는지 본다.
  - 방향: 탭 높이를 변수로 두고 `.rh`의 `top`과 `scroll-margin-top`을 함께 계산한다.
- **U-07 막대가 행 오른쪽 정보를 가린다**
  - 행 오른쪽에 상태 알약과 날짜가 있어, 스크롤 중 막대 밑에 깔린다.
  - 방향 선택지(사용자 결정): (a) 데스크톱에서 본문 오른쪽 여백 바깥에 막대를 둔다. (b) 스크롤을 내리는 동안 숨기고 올릴 때 보인다. (c) 현재 유지.
  - 재현 화면과 함께 추천을 적는다.

## 3. 같은 종류로 더 찾을 것

아래 항목으로 전체 화면을 훑는다. 찾은 것마다 번호(U-08부터), 화면, 폭, 모드, 스크린샷 경로, 원인 선택자, 고칠 방향을 적는다.

- **다크 모드**
  - `--ink`를 테두리나 면에 그대로 써서 흰 덩어리로 보이는 곳
  - 그림자나 투명도가 다크 바탕에서 사라지는 곳
  - 하드코딩 색(`#`, `rgba(` 직접 값)
- **크기 일관성**: `--tap`, `--fs-*`, `--sp-*`를 쓰지 않은 고정 px(44px, 45px, 56px 등). 같은 역할의 컨트롤끼리 높이와 모서리가 다른 곳.
- **겹침과 가림**:
  - fixed·sticky 요소(탭, 구역 머리, 막대)가 본문, 초점 테두리, 앵커 이동 위치를 가리는 곳
  - z-index 충돌
  - sticky 머리 아래로 본문이 비쳐 보이는 곳
- **넘침**:
  - 긴 이름, 팀명, 출처 줄, 주소가 줄을 넘치거나 가로 스크롤을 만드는 곳(375px, 확대 200%)
  - 모바일 가로 스크롤 줄 끝의 흐림 처리가 마지막 칩을 가리는 곳
- **초점과 키보드**:
  - `:focus-visible` 테두리가 잘리거나 sticky 요소 밑에 숨는 곳
  - 막대가 보이지 않을 때도 Tab 순서에 남는지
  - 상세 화면 전환 뒤 초점 위치
- **상태 표시**:
  - 눌린 칩, 현재 탭의 구분이 색 하나에만 기대는 곳
  - 비활성 버튼의 대비
  - 빈 목록, 검색 0건, 없는 주소 문구의 위치와 모양
- **글자**:
  - 한 줄짜리 글의 세로 가운데 맞춤(알약, 배지, 칩 안의 숫자)
  - 숫자 `tabular-nums` 누락
  - 13px 미만 글자
- **움직임**: `prefers-reduced-motion`일 때도 부드러운 스크롤이나 전환이 남아 있는 곳
- **인쇄·확대**: 확대 200%에서 막대나 sticky 요소가 화면의 큰 부분을 덮는지

## 4. 고치는 방법

- 토큰을 먼저 만든다. 예: `--dock-h`, `--dock-gap`, `--tabs-h`, 모드별 `--shadow-float`, `--line-strong`. 그다음 규칙이 그 토큰을 쓰게 한다. 같은 숫자를 여러 곳에 쓰지 않는다.
- 선택자를 새로 늘리기보다 기존 규칙을 고치거나 합친다. css 끝에 덮어쓰기 규칙을 덧붙이지 않는다. 같은 선택자는 한 곳에만 둔다.
- 라이트와 다크를 같이 고친다. 한쪽만 고치지 않는다.
- js는 화면 동작에 꼭 필요할 때만 바꾼다(U-06 스크롤 위치, U-07 선택 시). 데이터 처리 코드(`model.js`, `format.js`)는 건드리지 않는다.
- 고친 항목마다 같은 조건의 스크린샷을 `/tmp/ui-audit/after/`에 남긴다. 전후 비교 이미지(좌우로 붙인 것)도 만든다.

## 5. 확인

- 1장의 모든 조합을 다시 찍어 전후를 비교한다. 의도하지 않은 변화가 있으면 원인을 찾는다. 예: 다른 화면의 간격이 바뀐 것.
- 텍스트와 컨트롤 대비를 계산해 표로 남긴다. 본문·보조 글자는 4.5:1 이상, 테두리와 아이콘은 3:1 이상이어야 한다. 라이트와 다크 둘 다 확인한다.
- 시험 3종(test, validate, build)을 통과해야 한다.
- `_site` 상세 페이지 수와 sitemap 항목 수가 작업 전과 같아야 한다.
- 콘솔 오류가 0이어야 한다.

## 6. 보고와 마무리

1. 점검 결과 표를 만든다. 열은 번호, 항목, 화면·폭·모드, 재현 여부, 원인, 처리(고침 / 사용자 결정 / 재현 안 됨)다.
2. 고친 항목마다 전후 스크린샷을 붙인다. PR에는 중요한 것 몇 장만 넣는다.
3. 사용자 결정이 필요한 항목(U-07 등)은 선택지와 추천을 정리한다.
4. `docs/디자인/design-brief.md`에 새로 정한 규칙을 짧게 추가한다. 예: 떠 있는 컨트롤의 테두리·그림자 규칙, 막대 토큰.
5. `docs/PROGRESS.md`에 이번 회차 기록을 남긴다.
6. PR 제목은 "UI 세부 점검: 고정 막대, 다크 모드, 겹침·넘침 정리"로 연다. 병합은 하지 않는다.

## 하지 않는 것

- 새 기능, 색 체계·글꼴·레이아웃 방향 변경, 웹폰트 추가
- 데이터, 예약 작업, 배포 설정 변경
- 재현되지 않은 문제를 추측으로 고치는 것
