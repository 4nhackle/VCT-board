# VCT-board 16회차 지시문 — 디자인 토큰 정리, 컴포넌트 견본 페이지, 스타일 자동 점검

## 배경

- Astryx(Meta, React 19 + StyleX, 베타) 같은 디자인 시스템은 전면 적용하지 않기로 했다. 이 사이트는 의존성 없는 순수 JS·정적 빌드이고 300KB 예산을 두고 있다.
- 대신 디자인 시스템의 좋은 점 세 가지를 지금 구조에 맞게 들인다.
  1. **토큰을 층으로 나눈다**: 기본값 → 의미 → 컴포넌트
  2. **컴포넌트 견본 페이지**를 만든다
  3. **스타일 규칙을 자동으로 점검**한다
- 목표: 8·12·15회차처럼 모바일 깨짐, 크기 위계, CSS 중복 같은 문제를 사람이 화면을 보고 찾기 전에 잡는다.
- **이 회차는 15회차(팀 머리·모바일) PR이 병합된 뒤에 시작한다.** 병합 전이면 아무것도 바꾸지 말고 보고한다.

## 0. 지킬 것

- `main` 최신에서 브랜치 `feature/design-tokens`를 만든다. 항목마다 커밋을 하나씩 만들고, 커밋 메시지 앞에 `D-1:` 같은 번호를 붙인다.
- **화면은 바뀌지 않는다.** 이번 회차는 정리 작업이다. 한국어·영문 화면 모두에서 계산된 스타일과 DOM이 작업 전후로 같아야 한다(D-2의 확인 방법).
- 다음은 건드리지 않는다.
  - `data/`
  - `index.html`의 `<p class="lede">`와 기준 시각 형식
  - `<script type="module" src="js/main.js">`
  - 번역 키·검사 규칙
  - 판정 정규식
- 외부 패키지와 웹폰트를 추가하지 않는다. CI(`pages.yml`)는 지금처럼 Node만 쓴다. 브라우저가 필요한 점검은 CI 밖의 수동 스크립트로 둔다.
- 단계마다 아래 세 명령이 통과해야 한다.
  - `node scripts/test.mjs`
  - `node scripts/validate.mjs`(오류 0)
  - `node scripts/build.mjs _site`
- 병합은 예약 작업 실행 시각 앞뒤 30분을 피한다. 실행 시각은 08:50·09:35, 11/16까지 14:50·15:35·20:50·21:35 KST다. 이 내용을 PR 설명에 적는다.

## D-1. 토큰 층 나누기 (`css/style.css`)

지금은 `:root`에 `--fs-1..6`, `--sp-1..7`, `--r-*`, `--tap`, 색 변수가 한 층으로 있다. 규칙들은 이 값을 직접 쓴다. 이를 세 층으로 나눈다.

| 층 | 이름 예 | 어디서 정의 | 누가 쓰나 |
|---|---|---|---|
| 기본값 | `--fs-1`…`--fs-6`, `--fs-team`, `--sp-1`…`--sp-7`, `--r-1`·`--r-2`·`--r-pill`, 원색(`--green-600` 등 실제 색값) | `:root`와 다크 블록만 | 의미 토큰만 |
| 의미 | `--text-region`, `--text-team`, `--text-name`, `--text-body`, `--text-meta`, `--color-ink`, `--color-mute`, `--color-line`, `--color-line-strong`, `--color-accent`, `--surface`, `--surface-float`, `--space-section`, `--space-row`, `--control-h`(=`--tap`), `--radius-control`, 상태별 `--status-open-bg` 등 | `:root`(라이트)와 다크 블록(같은 이름, 다른 값) | 컴포넌트 규칙 |
| 컴포넌트 | 필요할 때만. 예: `--chip-h`, `--row-rail-w` | 그 컴포넌트 규칙 맨 위 | 그 컴포넌트 |

- **규칙**: `:root`와 테마 블록 밖의 CSS는 의미 토큰(또는 컴포넌트 토큰)만 쓴다. 기본값 토큰이나 날것의 값을 직접 쓰지 않는다.
  - 예외: `0`, `1px`·`2px`·`3px` 테두리 두께, `100%`, `auto`, `none`, `inherit`, `currentColor`, `transparent`
  - 예외가 더 필요하면 목록을 보고하고 사용자 결정으로 둔다.
- 다크 모드는 의미 토큰 값만 바꾼다. 지금 `prefers-color-scheme` 블록과 강제 다크 블록(약 26·38행)이 같은 값을 두 번 갖고 있다면 한 번만 정의되게 정리한다. 방법은 하나의 선택자 묶음이나 공통 변수 블록이다.
- 이름은 지금 역할을 그대로 옮긴다. 15회차의 위계 예: 지역 22 > 팀 19 > 이름 17 → `--text-region`·`--text-team`·`--text-name`.
- 사용되지 않는 토큰은 지운다. 지우기 전에 grep으로 확인하고 목록을 보고한다.

## D-2. 화면 불변 확인 방법 (먼저 만든다)

D-1을 하기 전에 비교 도구부터 만든다.

- `scripts/style-snapshot.mjs`(수동 실행, CI 밖, Playwright 필요)
  - 대상: 목록 각 탭, 인물 상세, 팀 상세, 일정, 건의, 없는 주소
  - 조합: 한국어·영문 × 라이트·다크 × 375·1280
  - 기록: 정해진 요소 목록의 계산된 스타일을 JSON으로 저장한다.
    - 요소: `.rh h2`, `.th`, `.name`, `.row`, `.chip`, `.pill`, `.tab`, `.search`, `.lang-switch a`, `.support-menu a`, `.dock`, `.dp-head`, `.dp-info dd`, `.kr-tag` 등
    - 속성: font-size, font-weight, line-height, color, background-color, border, padding, margin, gap, border-radius, min-height
  - 실행: `node scripts/style-snapshot.mjs out.json`, 비교는 `--compare before.json`. 다른 값만 출력한다.
- D-1 전후로 돌려 차이가 0이어야 한다. 차이가 나면 원인을 찾아 고친다. 의도한 차이는 없다.
- `README.md`의 "로컬에서 실행" 절에 이 스크립트를 한 줄로 적는다. Playwright가 없으면 설치 방법도 같이 적는다.

## D-3. 컴포넌트 견본 페이지

- `dev/styleguide.html`(+ 필요하면 `dev/styleguide.js`)을 만든다. **배포하지 않는다.**
  - `build.mjs`가 `dev/`를 `_site`로 복사하지 않는지 확인한다. 복사한다면 제외 규칙을 넣는다.
  - `dev-server.mjs`의 `SERVED`에 `dev/`를 추가해 `http://localhost:8080/VCT-board/dev/styleguide.html`로 열리게 한다.
- 실제 사이트 CSS(`css/style.css`)와 실제 렌더 함수(`rowHTML`, `newsRow`, `pill`, `badge`, `routeHTML`, 인물·팀 머리 등)를 import해서 그린다. 견본 전용 마크업을 손으로 쓰지 않는다. 실제와 같아야 의미가 있다.
- **보여 줄 것**(각각 이름표와 쓰이는 클래스 표기):
  - 토큰 표: 의미 토큰 이름, 값, 미리보기(글자 크기, 색 칩, 간격 막대)
  - 머리: 지역 머리, 팀 머리(인원 1명·여러 명, 긴 팀명), 날짜 머리
  - 행: 구직 중, 합류 확정, 합류 보도, 팀 떠남, 확인 필요, 이동 경로, 잔류, 출처 시각·교차 확인, 긴 비고, KR 표시(영문)
  - 칩: 탭, 상태 요약(개수), 지역, 정렬(새 N 배지), 눌린 상태
  - 머리말: 제목, 문장, EN/KR 전환, 후원 메뉴
  - 상세: 모노그램, 정보 표(미공개 값), 경력 타임라인(진행 중), 이번 이동 카드
  - 고정 막대(바로가기, 맨 위로)
- **보기 전환**: 페이지 위쪽에 버튼을 둔다.
  - 라이트/다크(`color-scheme` 강제)
  - 한국어/영문(`setLang`)
  - 폭 미리보기 360·375·768·1280. iframe 폭을 바꿔 같은 페이지를 보여 준다.
- 샘플 데이터는 `scripts/fixtures`에서 가져온다. 긴 이름, 긴 팀명, 한글 팀 칸, 빈 값 같은 경계 사례를 fixture에 더한다. data/는 쓰지 않는다.

## D-4. 스타일 자동 점검 (CI 안, Node만)

`scripts/test.mjs`에 넣거나 `scripts/css-check.mjs`로 두고 시험에서 부른다.

1. **중복 선택자**: 같은 선택자 묶음이 같은 미디어 조건 안에 두 번 이상 나오면 실패한다. 8·12회차에 같은 문제가 두 번 있었다.
   - 예외: `:root`·테마 블록. 같은 이름의 의미 토큰을 다른 값으로 정의하는 것은 의도다.
2. **날것의 값 금지**: `:root`·테마 블록 밖에서 다음이 나오면 실패한다.
   - `#` 색, `rgb(`·`hsl(`
   - px 크기: D-1 예외 제외
   - 기본값 토큰 직접 사용: `var(--fs-`, `var(--sp-`, `var(--r-`, 원색 토큰
   - 실패 메시지에 줄 번호와 대신 쓸 의미 토큰을 제안한다.
3. **대비**: `:root`(라이트)와 다크 블록의 의미 색 토큰을 읽어 WCAG 대비를 계산한다.
   - 본문 글자 쌍(`--color-ink`/`--surface`, `--color-ink`/`--bg`, `--color-mute`/`--bg` 등)은 4.5:1 이상
   - 테두리·아이콘 쌍(`--color-line-strong`/`--bg`, 상태 띠/`--surface`)은 3:1 이상
   - 쌍 목록은 시험 안에 표로 둔다. 실패하면 두 색과 대비 값을 보여 준다.
4. **터치 크기 토큰**: 모바일 미디어 블록에서 `--control-h`(=`--tap`)가 44px 이상인지 본다.

- 지금 CSS가 이 점검을 통과하도록 D-1에서 고친다.
- 통과시키려고 예외를 늘리는 대신 규칙을 고친다. 예외가 꼭 필요하면 목록을 보고한다.

## D-5. 문서

- `docs/디자인/design-brief.md`의 "토큰" 절을 세 층 구조로 다시 쓴다. 의미 토큰 표에 이름, 용도, 라이트값, 다크값을 넣는다.
- "새 스타일을 넣을 때" 절차를 짧게 적는다.
  - 의미 토큰이 있으면 쓴다.
  - 없으면 의미 토큰을 먼저 만든다.
  - 견본 페이지에 예를 추가한다.
  - `css-check`를 통과시킨다.
- 외부 디자인 시스템(Astryx 등)을 쓰지 않는 이유를 한 단락으로 남긴다: 의존성 없음, 300KB 예산, 정적 빌드·시험 구조, 한글 타이포그래피.
