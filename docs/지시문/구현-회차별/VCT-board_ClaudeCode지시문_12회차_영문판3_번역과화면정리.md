## A. 본문 번역 저장소 (5단계)

### A-1. 방식: 원문 → 영문 대응표 한 파일

- 새 파일 `data/i18n-en.json`을 만든다. 형식은 `{ "한국어 원문 그대로": "English", ... }`다. 키 순서는 정렬해서 diff가 읽기 쉽게 한다.
- **행이 아니라 원문 글자를 키로 쓴다.**
  - 예약 작업은 매번 시트에서 data 파일을 다시 만든다. 그래서 행에 `note_en`을 붙이면 행이 바뀔 때마다 번역을 옮겨 줘야 한다.
  - 원문 글자를 키로 쓰면 같은 문장은 한 번만 번역된다. 예: "EG는 11/2 운영 종료…" 5행이 같은 문장이다.
  - 원문이 바뀌면 키가 달라져 자연히 다시 번역 대상이 된다.
- **대상 필드**: 한글이 들어간 값만 대상이다.

| 파일 | 필드 |
|---|---|
| players, coaches | `note`, `status`, `team` |
| transfers(players·coaches) | `note`, `type`, `from`, `to` |
| watch | `situation`, `targets`, `team` |
| schedule | `title`, `date`(문자열일 때), `source` |
| sources | 출처 이름(배열 첫 값) |
| people | `role`, `career[].role` |

- **비고의 기계 판독 부분은 원문 그대로 둔다.**
  - 끝의 보도 시각 `(출처이름 M/D HH:mm UTC|KST)`
  - `교차 확인: A, B` 구절
  - 화면의 `splitNote`가 영문 글에서도 이 둘을 똑같이 떼어 낼 수 있어야 한다.
  - 번역문 안에 이 부분을 글자 그대로 남긴다. "교차 확인:"도 번역하지 않는다. 화면에는 사전 문구 "Cross-checked"로 나온다.

### A-2. 화면 연결

- 영문 화면(`LANG === "en"`)에서만 `data/i18n-en.json`을 읽는다. 한국어 화면은 이 파일을 받지 않는다.
  - 파일이 없거나 읽기 실패하면 빈 표로 동작한다. 지금처럼 원문 + KR이다.
  - 로드 순서는 다른 data와 함께 `Promise.all`에 넣는다. 첫 화면을 그리기 전에 준비돼야 한다.
- `js/i18n.js`에 `trEn(text)`를 둔다. 대응표에 있고 **아래 검사를 통과하면** 영문을, 아니면 `null`을 돌려준다.
  - 영문에 한글이 없다.
  - 원문의 `splitNote` 결과와 영문의 `splitNote` 결과에서 보도 시각(출처 이름, 시각)과 교차 확인 목록이 같다.
  - 원문에 있는 숫자 묶음(날짜 `10/24`, 연도 `2028`, 시각 등)이 영문에도 모두 있다. 순서는 무관하다.
  - 검사에 실패한 번역은 쓰지 않는다. 지어낸 내용이 화면에 나오는 것보다 원문을 보여 주는 편이 낫다.
- **적용 순서**:
  - **비고**: 화면이 `splitNote(val(it.note))`를 부르는 모든 곳에서, 영문이면 `splitNote(noteText(it.note))`로 바꾼다. `noteText`는 `trEn(원문) ?? 원문`이다. 이후 `textHTML(body)`는 그대로 둔다(영문이면 한글이 없어 그대로 나온다).
  - **`textHTML`**(일정 제목, 상황, 출처 이름, 팀 칸 등): 대응표 → 원문 + KR
  - **`termHTML`**(상태·구분·역할·대상): 용어집(`termEn`) → 대응표 → 원문 + KR. 지금 용어집이 모두 처리하므로 대응표는 앞으로 새로 들어오는 문구의 대비책이다.
  - 사람 이름(`nameHTML`)은 번역하지 않는다.
- **번역 안내**: 영문 화면 하단 안내(`.notes`)의 KR 줄을 아래로 바꾼다. 문구는 en 사전에 둔다.
  - "English text is translated automatically from the Korean original. Items marked KR are not translated yet."
- 정적 빌드(`en/p/`, `en/t/`)의 og 설명에 비고를 쓰는 곳이 있으면 같은 `trEn`을 거친다. 없으면 그대로 둔다.

### A-3. 처음 번역 채우기

- 지금 `data/`에서 A-1 대상 문자열을 모두 모아(중복 제거) 번역해 `data/i18n-en.json`을 만든다.
  - 11회차 보고 기준으로 비고 약 165건, 상황 17, 일정 제목 10, 그 밖에 몇 건이다.
- **번역 규칙**:
  - 사실만 옮긴다. 원문에 없는 설명, 추측, 꾸밈말은 넣지 않는다. 짧고 건조한 보도체로 쓴다.
  - 선수·팀 이름, 약칭(C9, SEN, EG, PRX), 고유 용어(LFT, FA, VCT, IGL)는 그대로 둔다.
  - 용어는 `js/i18n/en.js`와 `js/i18n/glossary.js`의 영문과 같게 쓴다. 예: 탐색 허가 → Free to explore, 방출 → Released, 합류 보도 → reported to join, 공식 발표 전 → not yet official, 단일 출처 → single source.
  - 날짜는 원문 숫자 표기(`10/24`, `11/2`)를 그대로 둔다. A-2의 숫자 검사와 맞추기 위해서다.
  - A-1의 기계 판독 부분은 글자 그대로 둔다.
  - 한국 팀·인물의 한글 표기가 섞여 있으면 널리 쓰는 영문 표기로 쓴다. 확신이 없으면 그 문장을 대응표에 넣지 않는다(KR로 남김).
- **표본 검토**: 대응표 중 20건을 무작위로 골라 원문과 나란히 놓은 표를 보고서에 붙인다. 사용자가 품질을 판단하는 자료다.

### A-4. 검증 (`scripts/validate.mjs`)

- `data/i18n-en.json`이 있으면 다음을 **경고**로 점검한다. 배포를 막지 않는다.
  - JSON 형식
  - 값에 한글이 있음
  - A-2 검사 실패(보도 시각·교차 확인·숫자 불일치)
  - 대상 필드에 한글 원문이 있는데 대응표에 없음(번역 누락). 개수만 한 줄로 요약하고, 처음 10건을 보여 준다.
  - 대응표에 있지만 지금 data 어디에도 쓰이지 않는 키(낡은 번역). 개수만 보여 준다.
- 경고 문구에는 "예약 작업이 다음 실행에서 채운다"는 안내를 넣는다.
- `scripts/i18n-report.mjs`를 만든다. 대상 필드별 원문 수, 번역 수, 누락 수를 표로 출력한다. 부록의 예약 작업 점검과 같은 기준이다.

### A-5. 시험

- `trEn` 검사를 시험한다: 통과, 한글 남음, 보도 시각 바뀜, 교차 확인 바뀜, 숫자 빠짐, 대응표 없음.
- **영문 화면 한글 0**: 지금 data와 새 대응표로 영문 목록 7탭, 인물, 팀을 렌더한다. `lang="ko"` 밖 한글이 0이고, KR 표시 수가 크게 줄었는지 숫자로 보고한다(배포 화면 기준 131개였다).
- **한국어 화면 불변**: DOM이 기준선과 같아야 한다(B 머리말 제외). 한국어 화면이 `i18n-en.json`을 요청하지 않는지도 확인한다(네트워크 요청 목록).

## B. 화면 정리 (11회차 배포 뒤 발견)

### B-1. 영문 지역 머리 중복

- `js/views/regions.js`의 구역 머리는 `<h2>지역 이름</h2><span class="en">원문</span>` 구조다.
- 영문에서는 둘 다 "Americas"라 "Americas Americas"로 보인다.
- 영문에서 두 값이 같으면 `.en` 칸을 만들지 않는다. 한국어 화면("아메리카 Americas")은 그대로 둔다.
- 다른 화면(바로가기 고르기 상자의 항목, 인물·팀 상세)에서도 같은 중복이 있는지 찾아 같이 고친다.

### B-2. 머리말 배치

- **지금**: 왼쪽 칸에 제목, 문장, 후원 메뉴가 있고, 오른쪽 칸에는 EN/KR만 있다. `design-brief.md` 35행 규칙("오른쪽 후원 메뉴")과 맞지 않는다.
- **바꿀 모양**(두 언어 공통):
  - **601px 이상**: 왼쪽 칸은 제목·문장이다. 오른쪽 칸은 위에서 아래로 EN/KR 전환, 그 아래 후원 메뉴이고, 둘 다 오른쪽 정렬이다. 오른쪽 칸은 왼쪽 칸과 세로 가운데로 맞춘다. 칸 사이 간격은 `var(--sp-2)`다.
  - **600px 이하**: 한 칸으로 제목, 문장 순서다. 그 아래 한 줄에 후원 메뉴(왼쪽)와 EN/KR(오른쪽)을 양 끝으로 두고, 좁으면 줄을 바꾼다. 줄 간격은 `var(--sp-2)`, 가로 넘침은 없어야 한다.
  - 마크업은 오른쪽 칸을 `<div class="top-side">`로 감싸 두 nav를 넣는다.
  - 상세 화면(작은 `p.site`)에서도 같은 규칙이다.
- **확인**: 8회차와 같은 측정으로 확인한다.
  - 폭: 375·600·601·768·1280·1920
  - 모드: 라이트·다크
  - 확대: 100·200%
  - 판정: 링크 4개(KR, EN, Ko-fi, 카카오페이)가 모두 보이고 겹치지 않는다. 601px 이상에서 오른쪽 칸 오른쪽 끝이 본문 오른쪽 끝과 같다. 600px 이하에서 왼쪽 끝이 제목과 같다.
- `design-brief.md`의 머리말 규칙(35행)과 EN/KR 전환 규칙(64행)을 새 배치로 고친다.

### B-3. CSS 중복

- `css/style.css`에 `.lang-switch` 규칙 네 줄이 두 번 있다(약 92~95행, 99~102행). 하나로 합친다.
- 같은 방식으로 이번 영문판 작업에서 생긴 중복 선택자를 찾아 정리한다. 예: `.kr-tag`, `.kr-src`, `.top`.

## C. 영문 안내 페이지 (6단계)

- **건의 폼**(`js/views/suggest.js`): 영문 화면의 안내 문단, 라벨, 버튼이 모두 en 사전 문구인지 확인한다. 남은 한국어 안내 문단을 옮긴다. 보내는 메일 본문의 머리말("VCT Tracker page")은 영문이다. 사용자 입력은 그대로 보낸다.
- **약관·개인정보 영문 요약**: `en/terms/`, `en/privacy/`를 만든다.
  - 내용: 한국어 원문의 항목 순서를 따른 짧은 요약
  - 맨 위에 "This is a summary. The Korean original prevails."와 원문 링크를 둔다.
  - 법적 의미를 바꾸는 표현을 새로 만들지 않는다. 원문에 없는 약속은 넣지 않는다.
  - 원본은 저장소 `terms/`, `privacy/`와 같은 정적 HTML이다. 영문 페이지는 저장소에 정적 파일로 둔다(빌드 생성 아님). 빌드가 그대로 복사하는지, 사이트맵에 영문 두 주소와 `hreflang` 대응이 들어가는지 확인한다.
  - 영문 화면 푸터의 정책 링크는 이 영문 요약으로 바꾸고 "(Korean)" 표시를 지운다.
- **후원(영문 화면)**: 카카오페이 송금은 국내 계좌 송금이라 해외 사용자가 쓰기 어렵다. 영문 화면에서 카카오페이 링크를 숨길지는 **사용자 결정**이다. 이번에는 그대로 두고, 보고에 선택지로 적는다.

**삽입 위치**: [작업] 3) 안전 확인 앞에 새 항목 2-5)로 넣는다.

```
2-5) 영문 번역 저장소(data/i18n-en.json) 갱신:
 - 새로 만든 data 파일에서 한글이 든 문자열을 모은다: players·coaches 의 note·status·team, transfers 의 note·type·from·to, watch 의 situation·targets·team, schedule 의 title·(문자열이면) date·source, sources 의 이름, people 의 role·career[].role.
 - 기존 data/i18n-en.json 을 읽어(없으면 빈 표) 키에 없는 문자열만 번역해 더한다. 한 실행에 최대 80개. 넘치면 나머지는 다음 실행에 맡기고 보고에 "번역 대기 N개"로 적는다.
 - 번역 규칙: 사실만 짧게(원문에 없는 내용 금지), 선수·팀 이름과 약칭·LFT·FA·VCT·IGL 은 그대로, 날짜 숫자 표기(10/24, 11/2)는 그대로, 끝의 "(출처이름 M/D HH:mm UTC|KST)" 와 "교차 확인: …" 구절은 글자 그대로 남긴다. 용어: 탐색 허가 Free to explore, 방출 Released, 계약 완료(X) Signed with X, 합류 보도 reported to join, 공식 발표 전 not yet official, 제한적 FA Restricted FA. 확신이 없으면 그 문자열은 넣지 않는다.
 - 넣기 전 검사(하나라도 걸리면 그 항목만 버린다): 영문에 한글이 없다 / 원문의 숫자 묶음이 영문에 모두 있다 / 원문 끝의 보도 시각 괄호와 교차 확인 구절이 영문에 글자 그대로 있다.
 - 지금 data 어디에도 쓰이지 않는 키는 지운다.
 - 키를 정렬해 쓰고, 바뀌었으면 다른 data 파일과 같은 커밋에 넣는다. 이 파일만 바뀐 경우도 커밋한다(커밋 메시지에 "번역 +N").
 - 보고 한 줄 추가: "영문 번역 +N, 대기 N".
```
