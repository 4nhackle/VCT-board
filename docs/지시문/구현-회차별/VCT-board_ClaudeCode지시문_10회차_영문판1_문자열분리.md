# VCT-board 10회차 지시문 — 영문판 1: 화면 문구 분리와 영문 표기 형식

## 전체 계획 중 이번 회차의 위치

영문판은 아래 순서로 만든다. 이번 회차는 1~2단계다.

| 단계 | 내용 | 회차 |
|---|---|---|
| 1 | 화면 문구를 사전으로 분리. 한국어 화면은 한 글자도 바뀌지 않음 | **10** |
| 2 | 언어별 표기 형식: 시각, 상대 날짜, 인원·나이·계약 문구 | **10** |
| 3 | 상태 알약과 상태 용어집의 영문 | 11 |
| 4 | `/VCT-board/en/` 주소, 정적 빌드, EN/KR 전환 버튼 | 11 |
| 5 | 예약 작업이 비고·상황·일정 제목을 번역해 `*_en` 필드에 씀 | 12(예약 작업 변경) |
| 6 | 건의 폼, 약관·개인정보 영문 요약 | 12 |

뒤 단계에서 지킬 결정 사항이다. 이번 회차의 구조를 이 결정에 맞춘다.

- **주소**:
  - 영문판은 `/VCT-board/en/` 아래에 둔다(`en/`, `en/p/<id>/`, `en/t/<id>/`).
  - 지금의 한국어 주소는 그대로 유지한다.
  - 언어는 주소로만 정한다. 쿼리(`?lang=`)나 저장값으로 정하지 않는다.
- **전환**:
  - EN/KR 버튼은 같은 화면의 다른 언어 주소로 **페이지를 실제로 이동**한다(전체 로드). 화면 안에서만 바꾸지 않는다.
  - 이유: GoatCounter는 페이지 로드마다 세고, og와 `lang` 속성도 주소별로 맞아야 한다.
  - 고른 언어는 localStorage(`vct-lang`)에 기억한다. 첫 방문 자동 이동은 하지 않는다.
- **데이터 원문은 한국어 그대로 둔다.**
  - 상태 글자는 정규식 판정(`pillOf`, `joinStage`, `REPORTED_RE`, `/방출|결별|이탈/` 등)에 쓰이므로 절대 번역하거나 바꾸지 않는다.
  - 번역은 5단계에서 별도 필드로만 더한다.
  - 번역이 없으면 영문 화면에 한국어 원문을 보여 주고 작게 "KR" 표시를 한다(3~4단계).
- **GoatCounter**: 같은 사이트 코드 그대로 쓴다. 새 등록은 없다.

## 0. 지킬 것

- `main` 최신에서 브랜치 `feature/i18n-1`을 만든다.
- 다음은 건드리지 않는다.
  - `data/`
  - `index.html`(머리말 시각을 예약 작업이 매일 고친다. 정적 문구는 4단계에서 다룬다)
  - `terms/`, `privacy/`, `og.png`, `.github/`
- 이번 회차에는 `/en/` 주소, 버튼, 영문 빌드를 만들지 않는다. 사이트에 보이는 변화는 0이어야 한다.
- 단계마다 아래 세 명령이 통과해야 한다.
  - `node scripts/test.mjs`
  - `node scripts/validate.mjs`
  - `node scripts/build.mjs _site`
- 시작 전에 기준선 `node scripts/build.mjs /tmp/before_site`를 만든다.
  - 끝나면 새 빌드와 `diff -r`로 비교해 **완전히 같아야** 한다(빌드 날짜 줄 제외).
  - Playwright로 목록 각 탭, 인물 상세, 팀 상세, 일정, 건의 화면을 작업 전후로 찍어 픽셀 비교도 한다. 다르면 원인을 찾아 고친다.
- 줄 번호 대신 함수·변수 이름으로 찾는다.

## 1. 문구 조사 (먼저 보고)

1. `js/`, `scripts/build.mjs`에서 한글이 들어간 문자열을 모두 뽑아 표로 만든다.
   - 열: 파일, 함수, 문자열, 분류
2. 분류는 셋이다.
   - **UI**: 화면에 나오는 문구. 사전으로 옮긴다.
     - 예: 탭 이름(`TABS`의 label·hint·title), `TAB_NAME`, `REGION_KO`, `TIER_KO`, `STATUS_LABELS`
     - 예: 계약 상태 라벨("미공개", "만료됨", "오늘 만료" …), 알약 문구("구직 중", "팀 떠남", "확인 필요", "합류 확정", "합류 보도", "잔류" …)
     - 예: 지켜볼 팀 종류("철수·해체", "파트너십 탈락" …), 빈 목록과 없는 주소 문구, 버튼·aria 문구, 건의 폼, build.mjs의 제목 접미사와 설명 문장
   - **판정**: 한국어 데이터를 읽는 정규식과 비교 글자. 그대로 둔다.
     - 예: `/계약 완료/`, `/잔류/`, `/구직|탐색/`, `REPORTED_RE`, `/^\[확정\]/`, `/확인\s*(\d…)/`, `" 합류"` 검색
     - 이 문자열 옆에 `// 데이터 판정용: 번역하지 않는다` 주석을 단다.
   - **주석**: 그대로 둔다.
3. 데이터 글자와 UI 글자를 이어 붙여 문구를 만드는 곳을 따로 표시한다.
   - 예: `m[1] + " 합류"`, `j[1] + " 합류 보도"`, `it.next + " 합류"`, `pillText`의 `+ " 보도"`
   - 이런 곳은 2장의 매개변수 문구로 바꿀 대상이다.

조사 표를 보고한 뒤 진행한다.

## 2. 사전과 `t()` 만들기

- **파일**:
  - `js/i18n.js`: 언어 상태와 `t()`
  - `js/i18n/ko.js`, `js/i18n/en.js`: 문구 사전
  - 모두 브라우저와 Node 양쪽에서 import 된다. 최상위에서 `window`, `document`를 쓰지 않는다.
- **언어 결정**:
  - `js/i18n.js`에 `export var LANG`을 둔다.
  - 브라우저에서는 `location.pathname`이 사이트 루트 + `en/`으로 시작하면 `"en"`, 아니면 `"ko"`다.
  - 사이트 루트는 `state.js`의 `BASE`와 같은 방식(`import.meta.url` 기준)으로 구한다.
  - Node(빌드·시험)에서는 기본값 `"ko"`이고, `setLang(lang)`으로 바꿀 수 있다.
- **`t(key, params)`**:
  - 키는 점으로 구분한 영문이다. 예: `tab.players`, `pill.joinedTeam`, `contract.expired`
  - 매개변수는 `{team}`, `{n}`처럼 쓰고, 넣는 값은 그대로 끼운다. 이스케이프는 지금처럼 쓰는 쪽에서 `esc()`로 한다.
  - 키가 없으면 ko 값으로 대체한다. ko에도 없으면 키 자체를 반환하고, 시험에서 실패하게 한다.
- **기존 상수 처리**:
  - `REGION_KO`, `TIER_KO`, `TAB_NAME` 같은 객체는 언어별 값을 돌려주는 함수나 사전 참조로 바꾼다.
  - 다른 파일이 이 이름을 import 하고 있으면 이름은 유지하고, 안에서 사전을 참조하게 한다. 바깥 코드를 최소로 바꾼다.
  - 단, 상수를 모듈 로드 때 한 번만 만들면 Node에서 `setLang` 뒤에 반영이 안 된다. 쓰는 시점에 사전을 읽게 한다.
- **데이터 + UI 문구**:
  - "Sentinels 합류"처럼 데이터와 섞인 문구는 `t("pill.joined", { team })`로 바꾼다.
  - ko 사전 값은 `"{team} 합류"`처럼 지금 출력과 똑같게 둔다.
  - `pillOf`의 반환값을 `[kind, labelKey, params, stage, short]` 같은 구조로 바꾸는 것은 괜찮다. 다만 `pillOf`를 쓰는 모든 곳(목록, 상세, validate.mjs의 "unknown" 판정)이 같은 결과를 내야 한다.
- **영문 사전(`en.js`)**: 이번 회차에 모든 키를 채운다. 화면에는 아직 안 보이지만 시험으로 확인한다. 아래 용어를 따른다.

| 한국어 | 영문 |
|---|---|
| 선수 / 코치·스태프 / 한국 / 이적 완료 / 지켜볼 팀 / 일정 / 건의 | Players / Coaches & Staff / Korea / Completed / Teams to Watch / Schedule / Feedback |
| 아메리카 / 유럽·중동·아프리카 / 아시아태평양 / 중국 | Americas / EMEA / Pacific / China |
| 구직 중 | Looking for team |
| 새 팀 합류 / {team} 합류 | Joined new team / Joined {team} |
| 합류 확정 / 합류 보도 | Confirmed / Reported |
| 팀 떠남 / 방출 / 잔류 | Left team / Released / Stayed |
| 확인 필요 | Unverified |
| 철수·해체 / 파트너십 탈락 / 계약 만료 | Withdrawn / disbanded · Lost partnership · Contract expiring |
| 파트너 팀 / 어센션 팀 / 챌린저스 / 아카데미 | Partner / Ascension / Challengers / Academy |
| 미공개 / 만료됨 / 오늘 만료 | Not disclosed / Expired / Expires today |
| 출처 / 교차 확인 / 보도 | Source / Cross-checked / Reported |

- LFT, FA, IGL, VCT, Riot 같은 고유 용어와 선수·팀 이름은 번역하지 않는다.
- 위 표에 없는 문구는 같은 어조(짧고 사실적인 표현, 첫 글자만 대문자)로 정한다. 정한 문구는 보고에 목록으로 붙인다.

## 3. 언어별 표기 형식 (2단계)

`js/format.js`의 표기 함수가 언어를 따르게 한다. 시험할 수 있게 언어를 인자로 받을 수 있게 하고(기본값 `LANG`), 지금의 `today` 인자 방식도 유지한다.

| 항목 | ko (지금 그대로) | en |
|---|---|---|
| 보도 시각 | 10/25 오전 1:30 | Oct 25, 1:30 AM |
| 날짜 | 10/25 | Oct 25 |
| 상대 날짜(`relDate`, `dayWord`) | 오늘 / 어제 / 그제 | Today / Yesterday / 2 days ago |
| 시간대 | KST | KST (그대로) |
| 인원 | 3명 | 3 players (코치 구역은 3 staff) |
| 나이 | 24세 | 24 |
| 계약 | 2027년 11월까지 같은 지금 문구 | until Nov 2027 |
| D-day | D-3 | in 3 days |

- 월 이름은 `Intl.DateTimeFormat("en-US", { month: "short", timeZone: "UTC" })`로 만든다. 날짜 일련번호를 UTC로 바꾸는 지금 방식과 맞춘다. Node 20과 브라우저 결과가 같은지 시험으로 확인한다.
- 날짜 계산(일련번호, `stampOf`, `parseStamp`, `TODAY`)은 바꾸지 않는다. 바꾸는 것은 글자 표기뿐이다.
- 위 표에 없는 표기도 1장 조사에서 찾아 같은 방식으로 처리한다.

## 4. 시험 (`scripts/test.mjs`)

- **사전 키 일치**: ko와 en의 키 집합이 같아야 하고, 빈 값이 없어야 한다. 매개변수 이름(`{team}` 등)도 두 언어가 같아야 한다.
- **ko 출력 불변**: 기존 시험이 모두 통과해야 한다. 1장 표의 대표 문구 몇 개는 출력 글자 그대로 고정한다.
- **en 화면에 한글 없음**:
  - `setLang("en")` 뒤에 `scripts/fixtures`의 샘플 데이터로 렌더 함수를 모두 돌린다.
    - 대상: `rowHTML`, `newsRow`, `personHTML`, `teamHTML`, 탭·요약·일정·지켜볼 팀 화면, 없는 주소 화면
  - 이때 샘플의 데이터 필드(이름, 비고, 상태 등)는 영문·숫자만 쓰도록 en 시험용 샘플을 따로 둔다.
  - 그러면 출력에 `[가-힣]`이 하나도 없어야 한다. 남으면 그 글자가 어디서 왔는지 시험 메시지에 보여 준다.
  - 단, 상태 판정이 한국어 글자에 기대므로 en 시험용 샘플의 상태 칸은 한국어 상태 글자를 쓴다. 이 칸은 화면에 직접 나오지 않고 알약 문구로 바뀌는 것을 함께 확인한다. 상태 원문이 그대로 화면에 나오는 곳이 있다면 목록으로 보고한다(3단계 대상).
- **표기 형식**: 3장 표의 각 항목에 ko와 en 시험을 하나씩 둔다. 자정 경계, UTC→KST 날짜 넘어감, 12시(오전·오후 12시와 12 AM·12 PM)를 포함한다.
- 시험 뒤에는 `setLang("ko")`로 되돌려 다른 시험에 영향이 없게 한다.

## 5. 확인과 마무리

1. `_site`를 기준선과 `diff -r`로 비교한다. 빌드 날짜 외에 차이가 없어야 한다.
2. 화면 픽셀 비교(라이트·다크, 375·1280)에서 차이가 없어야 한다.
3. 브라우저 콘솔 오류가 0이어야 한다.
4. 개발자 도구에서 `setLang("en")`을 수동으로 부르는 시험 진입로는 만들지 않는다. 화면은 4단계에서 연결한다.
5. 다음을 보고한다.
   - 1장 조사 표(분류별 개수)
   - 판정용으로 남긴 문자열 목록
   - 화면에 상태 원문이 직접 나오는 곳 목록(3단계 입력)
   - en 사전에서 새로 정한 문구 목록
6. `docs/PROGRESS.md`에 이번 회차와 위 "전체 계획" 표를 기록한다. `docs/디자인/design-brief.md`에 "문구는 `t()`로만 쓴다, 데이터 판정 정규식은 번역하지 않는다" 규칙을 추가한다.
7. PR 제목은 "영문판 1: 화면 문구 사전 분리와 영문 표기 형식(화면 변화 없음)"으로 연다. 병합하지 않는다.
