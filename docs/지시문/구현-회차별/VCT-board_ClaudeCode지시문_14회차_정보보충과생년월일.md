## A. 저장소 코드 (Claude Code)

### 0. 지킬 것

- `main` 최신에서 브랜치 `feature/info-fill`을 만든다. 항목마다 커밋을 하나씩 만들고, 커밋 메시지 앞에 `A-1:` 같은 번호를 붙인다.
- 다음은 건드리지 않는다.
  - `data/`
  - `index.html`의 `<p class="lede">`와 기준 시각 형식
  - `<script type="module" src="js/main.js">`
  - 번역 키·검사 규칙(`i18n-targets.mjs`, `trEn`, `noteParts`)
  - 판정 정규식
- 빈 값 판단은 `cleanName` 하나만 쓴다(13-2·13-3 규칙). 새 코드에 `!== "-"`를 직접 쓰지 않는다.
- 항목마다 아래 세 명령이 통과해야 한다.
  - `node scripts/test.mjs`
  - `node scripts/validate.mjs`(오류 0)
  - `node scripts/build.mjs _site`
- 기준선 `node scripts/build.mjs /tmp/before_site`를 만들어 두고, 끝나면 차이를 요약한다.
- 병합은 예약 작업 실행 시각 앞뒤 30분을 피한다. 실행 시각은 08:50·09:35, 11/16까지 14:50·15:35·20:50·21:35 KST다. 이 내용을 PR 설명에 적는다.

### A-1. 목록 행의 포지션·국적을 인물 정보로 보충

- **위치**: `js/model.js`의 `toItem`(player·coach 행의 `sub`), 또는 `buildIndex` 이후 목록을 그리는 곳.
- 행의 포지션(코치는 역할)·국적이 비어 있으면(`cleanName`), `personId`로 people.json을 찾아 `role`·`nationality`로 채운다.
- 행에 값이 있으면 행 값을 쓴다. 소식 시점의 값이기 때문이다.
- **역할 값 처리**: people.role이 "Initiator / IGL"처럼 여러 단어여도 그대로 쓴다. 영문 화면은 기존 용어집(`termHTML`)을 거친다.
- **검색**: 이름·팀 검색이 보충된 값(국적 등)에도 걸리는지 확인한다. 지금 검색 대상에 국적이 있다면 보충값도 포함한다.
- **확인**:
  - 지금 데이터로 목록에서 "-"로 보이던 국적이 약 30행, 포지션이 약 5행 채워지는지 숫자로 보고한다.
  - 한국 탭("국적이 South Korea") 집계가 달라지는지 확인한다. 달라지면 그 차이(새로 포함되는 선수)를 목록으로 보고한다. 보충값으로 한국 선수가 늘어나는 것은 의도한 변화다.

### A-2. 생년월일 공개

- **위치**: `js/views/person.js`의 정보 표(`info.age` 칸, 약 125~130행), 정적 빌드의 인물 설명(있으면)
- **지금**: "N세 (yyyy)"
- **바꿀 모양**:
  - 칸 이름을 "생년월일"(en "Born")로 바꾼다.
  - 값은 날짜와 나이를 함께 쓴다. ko "2003-05-21 (23세)", en "May 21, 2003 (age 23)"
  - 연도만 있으면 ko "2003년 (약 23세)", en "2003 (about 23)"
  - 값이 없으면 지금처럼 "미공개"를 흐리게 쓴다.
- **미성년자 예외**: 만 18세 미만이면 날짜를 숨기고 연도만 보여 준다(ko "2009년 (17세)").
  - 공개 자료에 있는 날짜라도 미성년 선수의 정확한 생일을 따로 모아 보여 주지 않는다.
  - 기준일은 `TODAY`다. 지금 데이터에서 해당하는 인물 수를 보고한다(현재 2명).
- **JSON-LD/메타**: 정적 상세 페이지에 `Person` 구조화 데이터가 있으면 `birthDate`를 위 규칙과 같게 넣는다(미성년자는 넣지 않음). 없으면 새로 만들지 않는다.
- 문구는 ko·en 사전에 둔다.
- **시험**: 날짜, 연도만, 없음, 만 18세 생일 전날·당일 경계, 영문 표기.

### A-3. 빈 정보 현황 스크립트

- `scripts/gaps.mjs`를 만든다. data/를 읽어 인물마다 비어 있는 항목을 모은다.
  - 대상 항목: 생년월일, 포지션(선수)·역할(코치), 국적, 본명, 경력, VLR 링크, Liquipedia 링크, 계약 만료
  - 출력 1(사람이 보는 표): 항목별 빈 칸 수, 선수·코치별
  - 출력 2(`--json` 옵션): 예약 작업이 쓸 작업 목록. 형식은 `[{ "id", "name", "kind", "team", "missing": [...], "vlr", "liquipedia" }]`
  - 정렬은 빈 항목이 많은 순, 같으면 현재 소식(LFT·이적)에 나오는 인물을 먼저 둔다.
- `scripts/validate.mjs`의 마지막 요약 줄에 "정보 빈 칸: 생년월일 N, 포지션 N, 국적 N, 계약 N"을 한 줄 더한다. 경고 수는 늘리지 않는다.
- 이 스크립트는 저장소 안에서만 돈다. data/에 파일을 쓰지 않고 표준 출력만 쓴다.

## B. 부록 — 시트 갱신 예약 작업 변경 (Claude Code는 적용하지 않음)

대상은 시트 갱신 작업 두 개(정기 08:50, 추가 14:50·20:50)다. [인물·팀 ID 규칙] 단락의 "정보 보충" 불릿과 "보충 인원 상한" 불릿을 아래로 바꾼다.

```
- 정보 보충(정해진 자리에서 찾는다 — 검색 스니펫으로 끝내지 말고 원문 페이지를 연다):
  · 생년월일·국적·본명: Liquipedia 선수 페이지 정보 상자(Born / Nationality / Name). 페이지는 '인물' 탭의 Liquipedia 링크, 없으면 liquipedia.net/valorant/<이름> 을 연다(동명이인은 팀 경력으로 확인). Born 이 날짜면 yyyy-mm-dd, 연도만이면 yyyy. 정보 상자에 없으면 VLR 선수 페이지, 그다음 구단 공식 소개 페이지. 나이만 적혀 있으면 생년월일을 추정하지 않는다.
  · 포지션(선수 역할): VLR 선수 페이지의 Agents 표(기간 60일, 기록이 없으면 90일·전체 순)에서 요원별 사용 라운드를 본다. 요원의 역할은 VLR·게임의 공식 분류(Duelist, Initiator, Controller, Sentinel)를 따른다. 한 역할이 사용 라운드의 60% 이상이면 그 역할, 아니면 상위 두 역할이 각각 30% 이상이면 "Flex", 기록이 20라운드 미만이면 Liquipedia 정보 상자의 Role 을 쓰고 그것도 없으면 비운다. IGL 은 Liquipedia·공식 발표가 IGL 이라고 할 때만 " / IGL" 을 붙인다. 이 값을 '인물' 탭 역할과, 'LFT 선수' 탭 포지션 칸이 비어 있거나 "-" 이면 그 칸에도 쓴다.
  · 계약: 구단 공식 X·웹사이트의 로스터·재계약·결별 발표를 먼저 본다(검색: "<팀명> contract", "<팀명> roster 2027", "<선수명> extension", 현지어 포함). 발표에 만료일이 날짜로 있으면 '인물' 탭 계약 만료에 쓴다. "2027 시즌까지"처럼 연도·시즌만 있으면 날짜를 지어내지 말고 '인물' 탭 계약 만료는 비우되 소식 탭 비고에 "계약 2027 시즌까지(구단 발표 M/D)" 로 적는다. 결별·방출 발표가 있으면 상태 칸과 신뢰도(확정)를 함께 고친다. Riot 공식 계약 데이터베이스가 열리면 그것을 근거로 써도 된다.
  · 국적: 정보 상자 값을 영문 국가명으로. '인물' 탭과, 'LFT 선수'·'코치·스태프' 탭 국적 칸이 비어 있거나 "-" 이면 그 칸에도 쓴다.
  · 모든 값은 원문을 연 출처를 '인물' 탭 출처 열에 =HYPERLINK 로 남긴다(Liquipedia 는 CC BY-SA 라서 링크 필수). 서로 다르면 Liquipedia > VLR > 매체 순으로 따르고 차이를 보고에 적는다. 확인되지 않은 값은 비운다(지어내지 않는다).
- 한 실행에서 정보를 보충하는 인물 수: 정기 실행은 새 인물 전부 + 빈 칸이 있는 기존 인물 최대 60명(빈 칸이 많은 순, 소식에 지금 나오는 인물 먼저), 추가 실행(11/2~11/16)은 새 인물 전부(최대 20명) + 빈 칸 있는 기존 인물 최대 10명. 보고에 "보충 N명(생년월일 +N, 포지션 +N, 국적 +N, 계약 +N) / 남은 빈 칸 N" 한 줄을 더한다.
```

## C. 부록 — 한 번에 채우는 보충 실행 (별도 적용)

- 기존 인물의 빈 칸이 생년월일 21, 포지션 65, 국적 14, 계약 전원이다. 정기 실행 60명씩으로는 며칠이 걸린다.
- 그래서 한 번만 도는 예약 작업을 두 번(각 70명 안팎) 둔다. 시트 갱신·웹 반영 실행과 겹치지 않는 시각에 B와 같은 절차로 '인물' 탭과 소식 탭 칸만 채운다.
  - 새 소식 조사와 정렬 변경은 하지 않는다.
  - 탭 순서와 열은 건드리지 않는다.
- 모델은 Sonnet을 쓴다.
- 결과는 다음 웹 반영 실행이 사이트에 올린다.
