# VCT-board 6회차 지시문 — 구조 개선 (중복 제거 · 이스케이프 시험 · 탭 이름 단일화)

적용 시점: S4-03(시트 '인물'·'팀' 전환, people.json·teams.json 첫 배포)이 끝나고 사이트가 정상 배포된 뒤.
성격: 동작은 바꾸지 않는 정리 작업이다. 화면과 생성되는 주소(p/<id>/, t/<id>/, sitemap)는 작업 전후로 똑같아야 한다.

## 0. 먼저 지킬 것

- 작업 브랜치 `refactor/structure-6` 를 main 최신에서 새로 만든다. main 에 직접 커밋하지 않는다.
- data/ 아래 JSON, index.html 의 머리말 시각, og.png 는 건드리지 않는다. (예약 작업이 data/ 를 자동 커밋하므로 충돌을 피한다.)
- .github/workflows 는 R-03 에서 필요한 경우에만 고친다. 그 외에는 건드리지 않는다.
- 각 단계는 아래 순서대로, 단계마다 `node scripts/test.mjs` · `node scripts/validate.mjs` · `node scripts/build.mjs _site` 가 모두 통과해야 다음으로 넘어간다. 하나라도 실패하면 그 단계를 되돌리고 원인을 보고한다.
- 수정 전에 먼저 조사하고, 조사 결과를 한 번 보고한 뒤 진행한다. 예상과 다르면(예: 중복이 없으면) 그 단계는 "변경 없음"으로 기록하고 넘어간다. 억지로 바꾸지 않는다.
- 시작 전 기준선: 현재 main 에서 `build.mjs` 를 돌려 `_site` 를 `/tmp/baseline_site` 로 복사해 둔다(R-01 의 비교에 쓴다).

## R-01. 빌드와 브라우저 로직 중복 제거 (가장 중요)

조사:
1. `scripts/build.mjs` 의 `newestFirst()`, `teamNameOf()` 와 그 밖의 정렬·이름 조회·날짜 계산 함수를 모두 찾는다.
2. `js/model.js`, `js/format.js`, `js/common.js` 에 같은 일을 하는 함수가 있는지 비교한다(이름이 달라도 하는 일이 같으면 중복이다). 특히 `esc`, `idsOf`, `slugOf`, `careerOf`, `ageOf`, `contractState`, `isoOf`, 팀 이름 조회, 최신순 정렬.
3. build.mjs 가 이미 model.js·common.js 를 import 하는지, 어떤 함수를 따로 다시 만들었는지 표로 보고한다(함수, 위치, 중복 여부, 동작 차이).

수정:
- 동작이 같은 중복은 build.mjs 가 js/ 쪽 함수를 import 해서 쓰게 바꾸고 build.mjs 안의 복사본을 지운다.
- 동작이 다른 중복은 임의로 한쪽에 맞추지 말고, 차이와 어느 쪽이 의도인지 보고한 뒤 멈춘다(사용자 결정).
- js/ 파일은 브라우저와 Node 양쪽에서 import 가능해야 한다. 브라우저 전용 API(window, document) 를 최상위에서 쓰고 있어 import 가 안 되면, 순수 함수만 model.js 로 옮기는 정도까지만 하고 DOM 에 닿는 코드는 옮기지 않는다.

확인:
- 작업 후 `_site` 를 `/tmp/baseline_site` 와 `diff -r` 로 비교한다. 파일 목록, p/·t/ 페이지, sitemap 이 바이트 단위로 같아야 한다. 다르면 차이를 보고하고 원인을 설명할 수 있는 경우(예: 빌드 시각)만 허용한다.

## R-02. 렌더 출력 이스케이프 시험 추가

목표: 데이터에 HTML 이 섞여도 렌더 결과에 날것으로 남지 않음을 자동으로 확인한다.

1. 렌더 함수를 모두 찾는다: `rowHTML`, `newsRow`, `personHTML`, `teamHTML`, `badge`, `pill`, `link` 와 그 밖에 HTML 문자열을 만드는 함수.
2. `scripts/test.mjs`(또는 기존 시험 구조에 맞는 위치)에 시험을 추가한다.
   - 가상 데이터는 scripts/fixtures 안에만 둔다(실제 data/ 를 쓰지 않는다).
   - 모든 문자열 필드(이름, 본명, 국적, 역할, 비고, 팀명, 별칭, 경력의 team·role·from·to, 링크, 출처)에 `<img src=x onerror=alert(1)>` 와 `"><script>x</script>` 를 넣고 위 렌더 함수를 돌린다.
   - 출력에 `<img src=x`, `<script>`, 닫히지 않은 속성 따옴표 탈출(`"><`)이 그대로 있으면 실패한다. 이스케이프된 `&lt;` 형태는 통과한다.
   - 링크 필드에 `javascript:` 주소를 넣어도 href 로 나가지 않음을 확인한다(이미 막혀 있다면 그 사실을 시험으로 고정한다).
3. 시험이 실패하는 곳이 있으면 그 렌더 함수에 `esc()` 를 적용해 고치고, 어떤 필드가 새고 있었는지 보고한다.
4. 정적 빌드(build.mjs)가 만드는 페이지의 `<title>`, meta, og 태그, JSON-LD 등에도 같은 값을 넣어 보고, 이스케이프되는지 확인한다.

## R-03. 시트 탭 이름 단일 출처화

조사:
1. 시트 탭 이름('LFT 선수', '코치·스태프', '관망 대상(미확정)', '성사된 이적', '인물', '팀', '변경 내역', '일정', '요약')과 `TAB_NAME` 이 코드 어디에 있는지 grep 한다. 쓰이지 않는 상수는 목록으로 보고한다.
2. 저장소 안에서 탭 이름이 문자열로 따로 박힌 곳(scripts/, docs/, fixtures)을 찾는다.

수정:
- 탭 이름이 코드에서 실제로 쓰이는 곳이 있으면 한 파일(예: scripts/constants.mjs 또는 기존 상수 파일)에 모으고 나머지는 거기서 가져다 쓴다.
- 쓰이지 않는 `TAB_NAME` 은 지운다. 단, 지우기 전에 어디에서도 참조되지 않음을 grep 으로 확인해 보고한다.
- 예약 작업 지시문(Claude 쪽)에 있는 탭 이름은 저장소 밖이라 고칠 수 없다. 대신 `docs/` 에 "탭 이름이 바뀌면 함께 고칠 곳" 목록을 `docs/PROGRESS.md` 에 한 줄 추가한다(코드 상수 위치, 웹 반영·시트 갱신 예약 작업 지시문).
- `scripts/validate.mjs` 가 data/ 의 구조만 보고 시트 탭 이름은 모른다면, 억지로 연결하지 않는다.

## R-04. 마무리

1. 위 단계 중 "변경 없음"으로 끝난 것이 있으면 그 이유를 한 줄씩 적는다.
2. `docs/PROGRESS.md` 에 R-01~R-03 결과(바꾼 파일, 지운 중복, 추가한 시험, 남은 문제)를 기록한다.
3. 전체 시험 3종(test, validate, build)과 `_site` 비교 결과를 붙여 PR 을 연다. PR 제목은 "구조 개선: 빌드 로직 중복 제거, 이스케이프 시험, 탭 이름 단일화". 병합은 하지 않고 사용자에게 맡긴다.
4. 보고 형식: 단계별 (조사 결과 / 바꾼 것 / 확인 결과) 와 사용자 결정이 필요한 항목 목록.
