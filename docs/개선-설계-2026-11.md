## 1. 항목별 설계

### 1.1 예약 작업 프롬프트에 출처 명시 (P + S 소량)

**문제**: 지시문이 어디를 조사할지, 무엇을 출처로 인정할지 정하지 않았다. 그래서 출처가 X 계정, 중국 커뮤니티(什么值得买), 2차 인용("TalkEsport(FUT 공식 X 인용)") 등으로 흩어진다. 같은 소식의 신뢰도(C/R) 판단도 실행마다 다르다.

**설계**

1. 지시문에 출처 등급표를 넣는다.

   | 등급 | 출처 | 쓰임 |
   |---|---|---|
   | A 공식 | 팀·선수 공식 X·웹사이트, Riot/VCT 공식 발표 | 단독으로 `conf=C`(확정), `signedDate` 기록 가능 |
   | B 보도 | Sheep Esports, Dot Esports, TheSpike, Strafe, VLR 뉴스·이적 로그 | 단독이면 `conf=R`, 서로 다른 B 두 곳이면 C |
   | I 인물 정보 | Liquipedia(CC BY-SA, 출처 표기 필수), VLR 선수 페이지 | 인물·팀 탭 칸만 채운다. 소식 근거로 쓰지 않는다 |
   | X 금지 | 커뮤니티 글, 출처가 없는 루머, 원문을 찾을 수 없는 재인용 | 쓰지 않는다. 재인용이면 원문을 찾아 원문을 출처로 쓴다 |

2. 조사 순서를 정한다: VLR 이적 로그 → Sheep Esports → 각 권역 팀 공식 X → Liquipedia 이적 페이지.
3. 출처 칸에는 기사 주소(경로까지)를 쓴다. 사이트 첫 화면 주소는 쓰지 않는다.
4. 보고에 출처 등급별 건수 한 줄을 추가한다.

**사이트 쪽(S)**: `scripts/validate.mjs` 에 경고 두 개를 추가한다(오류가 아니므로 배포를 막지 않는다).
- 출처 주소가 `https://` 가 아니거나, 경로가 없는 첫 화면 주소인 경우
- 같은 주소가 서로 다른 출처 ID 로 두 번 이상 나오는 경우

**지시문 문안 (시트 갱신 작업 두 개에 추가)**

```text
## Sources
Use only these sources, in this order of lookup:
1. VLR transfer log (vlr.gg/transfers) and VLR news
2. Sheep Esports
3. Official team / player / Riot VCT accounts (X, website)
4. Liquipedia transfer pages
Source tiers:
- A (official): team, player, Riot/VCT official posts. Alone is enough for conf=C and for signedDate.
- B (press): Sheep Esports, Dot Esports, TheSpike, Strafe, VLR news/transfer log. One B source = conf=R. Two independent B sources = conf=C.
- I (profile data): Liquipedia (CC BY-SA, always keep the link), VLR player pages. Use only for People/Teams tab fields, never as the basis for a news row.
- Forbidden: community posts, unsourced rumors, re-quotes whose original you cannot open. If a story is a re-quote, find and cite the original.
Every source cell must be a =HYPERLINK to the exact article or post URL (with path), never a site homepage.
Never invent a value. Leave a cell empty if no A/B/I source confirms it.
In the final report add one line: "sources: A n / B n / I n".
```

### 1.2 생년월일 (P)

**현재**: 사이트 표시는 끝났다(14회차: 날짜, 미성년은 연도만, 없으면 "미공개"). 남은 것은 **빈 칸 62명**(184−122)이다.

**설계**: 데이터만 채운다. 사이트 변경 없음.
- 정기 실행(08:50)에서 생년월일이 빈 인물을 한 번에 최대 15명, Liquipedia 인포박스 "Born" 으로 채운다. 하루 세 번 도는 기간에도 실행 시간이 늘지 않게 정기 실행만 맡는다.
- 우선순위는 `node scripts/gaps.mjs --json` 순서와 같게 "현재 LFT·이적 탭에 있는 인물 먼저"로 적는다.
- 연도만 확인되면 `yyyy`. 추정 나이는 쓰지 않는다.

```text
## Birth dates (daily 08:50 run only)
Fill up to 15 empty "생년월일" cells in the People tab per run, people who appear in current LFT/transfer rows first.
Use the Liquipedia infobox "Born" field. Write yyyy-mm-dd, or yyyy if only the year is shown. Never estimate.
```

### 1.3 계약 현황 · 1.4 계약 기간 (D + S + P)

**현재**: 칸(`contractUntil`, 인물·목록·이적 행)과 표시(`contractState`: D-n·오늘 만료·만료됨, 인물 상세)는 있다. 하지만 값이 있는 인물은 184명 중 1명뿐이다. 계약 정보는 대부분 상태 글 안에만 있다(예: "팀 이탈(KRÜ 이탈 보도 · 계약은 2028까지)"). 보도도 대부분 날짜 없이 연도만 말한다.

**설계**

1. **연도만 있는 계약 만료 허용 (D)**: `contractUntil` 에 숫자(시트 일련번호) 외에 `"yyyy"` 문자열을 허용한다. 생년월일과 같은 규칙이다.
   - `js/model.js` `contractState(until)`: 문자열 `yyyy` 이면 `{kind: "year", label: "2027년까지"}`. 올해보다 이전 연도면 만료됨.
   - `scripts/validate.mjs` 106·115행: 숫자 또는 `^\d{4}$`.
   - 사전 `contract.year` (ko "{y}년까지", en "through {y}").
   - 시험: `contractState("2027")`, `contractState("2025")`, validate 의 숫자·연도·잘못된 값.
2. **계약 현황 = 상태 + 만료 (S)**: 칸을 새로 만들지 않는다. "현황"은 이미 있는 LFT 상태(구직·합류·떠남)와 `contractUntil` 을 함께 보여 주는 것으로 정한다.
   - 목록 행 meta 줄(포지션·국적 뒤)에 계약 만료가 있으면 "계약 ~2027" 을 붙인다. `rowHTML` 의 `meta` 만 바꾼다.
   - 인물 상세는 지금 표시를 그대로 쓴다(연도 표시만 추가).
3. **데이터 채우기 (P)**: 출처는 A 등급 공식 발표, B 등급 보도에 적힌 날짜·연도, Riot 공식 계약 데이터베이스다. Riot 데이터베이스는 공개 주소와 접근 가능 여부를 지시문 반영 전에 사용자가 확인한다. 상태 글에 이미 적힌 "계약은 2028까지" 같은 값은 최초 1회 시트에 옮긴다.

```text
## Contracts
"계약 만료" (People tab, LFT rows, transfer rows): write a date only if an A source or a B report states the exact date.
If only the year is known ("contract until 2027"), write the 4-digit year as text: 2027.
One-time backfill: for every row whose status text already says "계약은 YYYY까지" or similar, copy the year into "계약 만료".
Never infer a contract end from the season end alone.
```

**순서**: 사이트 PR(연도 허용) 병합 → 웹 반영 작업의 안전 확인 규칙을 "숫자 또는 yyyy" 로 변경 → 시트 갱신 지시문 변경. 거꾸로 하면 Actions 검증이 실패해 배포가 멈춘다.

### 1.5 선수 캡션 업데이트 = 목록 행 설명글 (D + S + P)

**문제**: 행 설명글(`note`)은 소식이 생길 때마다 " / " 로 이어 붙인 이력이다. TenZ 행처럼 한 행이 네 문장을 넘는다. 오래된 내용과 지금 상황이 섞이고, 순서도 실행마다 다르다. 마지막 조각은 팀 공통 배경(`sharedTails`)으로도 쓰여 바꾸기 어렵다.

**설계**: 이력과 현재 요약을 나눈다.
- 시트 LFT 선수·코치·성사된 이적 탭 맨 오른쪽에 **"요약"** 열을 추가한다. JSON 칸은 `caption`(문자열, 120자 이하)이다.
- 지시문: 요약은 매 실행마다 **덮어쓴다**(이어 붙이지 않음). 지금 상황 한 문장이다. 비고(note)는 지금처럼 이력으로 둔다.
- 사이트
  - `toItem` 에 `caption: r.caption` 을 추가한다.
  - `rowHTML`: caption 이 있으면 설명글 자리에 caption 을 쓰고, 출처 줄은 그대로 둔다. 없으면 지금 동작(note) 그대로다. 그래서 데이터가 채워지기 전에도 화면이 바뀌지 않는다.
  - 인물 상세의 소식 카드는 note 전체(이력)를 그대로 보여 준다.
  - `validate.mjs`: caption 이 문자열이 아니면 오류, 120자를 넘으면 경고.
  - 영문 화면: caption 도 `data/i18n-en.json` 번역 표 대상에 넣는다(`scripts/i18n-targets.mjs`).
- 시험: caption 있음·없음 행의 rowHTML, validate 규칙.

```text
## Caption ("요약" column, LFT players / coaches / transfers)
One sentence (max 120 chars, Korean) describing the player's CURRENT situation, e.g. "Sentinels 공식 영입 발표(11/2)".
Overwrite it on every run when the situation changes; never append. Keep the full history in "비고" as before.
```

### 1.6 한국 탭 갱신 (S)

**문제** (`js/model.js` 62~63행)
- 선수: 행의 국적 글자에 "South Korea" 가 있어야 한다. 국적이 빈 행은 인물 정보로 보충된 뒤에만 잡힌다.
- 코치: `KR_TEAMS` 정규식(T1, KIWOOM DRX, Nongshim RedForce, Gen.G, DRX)에 맞는 팀 소속만 잡힌다. 그래서 해외 팀의 한국인 코치(인물 정보상 argency, cheonggak, kdg, termi, hype)는 빠진다. teams.json 의 한국 팀 9개 중 ONSIDE·Vision Strikers 등도 빠진다.
- 안내 문구(`hint.korea`)가 팀 3개만 말한다.

**설계**: 규칙 하나로 통일한다. **"국적이 한국이거나, 한국 팀(teams.json `country: "South Korea"`) 소속"**이면 선수·코치 모두 한국 탭에 넣는다.
- 국적은 행 값을 쓰고, 없으면 people 값(이미 `fillRow` 가 채움)을 쓴다. 코치 행에도 판정용으로 people 국적을 쓴다(화면에는 지금처럼 역할만 보인다).
- 팀은 `it.tid` → `TEAM_OBJ[tid].country` 로 본다. `KR_TEAMS` 상수를 지운다.
- 1.7 의 이적 병합 뒤 목록에서 거르므로, 한국 선수의 성사된 이적도 같이 들어온다.
- `hint.korea` ko·en 문구를 규칙에 맞게 고친다.
- 시험: 해외 팀 한국인 코치 포함, 한국 팀 외국인 선수 포함, 국적 빈 행이 people 국적으로 포함.

### 1.7 성사된 이적이 선수 탭에 반영되지 않는 버그 (S + P)

**재현** (현재 데이터)
- 이적 행은 있는데 선수·코치 탭에 아예 없는 인물: 9명. 예: GLYPH(ENVY → Cloud9, 공식 발표), KEN(→ ZETA, 공식), Sacy(→ T1, 공식), cortezia, canezerra, Hype 등.
- 이적은 공식 확정(`signedDate`)인데 선수 탭은 아직 "합류 보도"인 행: d4v41.
- 원인: 선수 탭은 'LFT 선수' 시트 행만 보여 준다. 그 행의 상태 글은 '성사된 이적' 탭과 따로 손으로 갱신된다. 같은 사실이 두 곳에 있어, 한쪽만 고치면 어긋난다.

**설계**: 사이트에서 이적 행을 기준(단일 출처)으로 삼아 선수·코치 목록에 합친다. 시트 쪽 동기화 규칙도 함께 넣는다.
- `buildTabs` 에서 인물 ID 별 "최신 이적 항목"을 만든다(날짜 최신, 같은 날이면 `signedDate` 있는 것).
- LFT 항목에 같은 인물의 이적이 있고 이적 날짜가 LFT 날짜보다 같거나 늦으면, 항목을 이적 기준으로 덮는다. `moved: true, next, signed, status(type), date` 는 이적 값을 쓰고, `team`·`note`·`sub` 는 LFT 값을 유지한다. `pillOf`·`routeOf` 는 이미 `moved` 를 처리하므로 바꾸지 않는다.
- LFT 행이 없는 이적 인물은 이적 항목을 목록에 추가한다(이적 선수 구역이면 선수 목록, 코치 구역이면 코치 목록).
- 상태 개수(요약 칩)와 한국 탭은 합친 목록에서 세므로 자동으로 맞는다.
- 성사된 이적 탭은 그대로 둔다.
- 시험(fixture): (a) 이적만 있는 인물이 선수 탭에 "합류" 로 나온다. (b) 확정 이적이 있는 "합류 보도" 행이 확정 알약으로 바뀐다. (c) LFT 날짜가 더 늦은 행(이적 뒤 다시 방출 등)은 덮지 않는다. (d) 잔류 이적은 잔류 알약이다.
- 지시문(P):

```text
## Transfer sync
When you add or update a row in "성사된 이적", update the same person's row in "LFT 선수" / "코치·스태프" in the same run
(status "계약 완료(<new team>)", same date). If the person has no LFT row, do not create one; the site merges transfer rows automatically.
When a transfer becomes official, fill "성사일" and set conf=C.
```

### 1.8 팀 소식 (계약 종료 등) (S, 1.3 데이터에 의존)

**현재**: 팀 상세(`teamMoves`)에는 로스터, 들어온·나간 인물, 관련 소식(관망 행 포함), 운영 종료 표시가 있다. 하지만 팀 단위 사건(로스터 계약 만료, 철수·파트너십 탈락)이 따로 정리되지 않는다.

**설계**: 팀 상세에 **"팀 소식"** 묶음을 하나 추가한다. 새 데이터는 만들지 않고 있는 것을 모은다.
- 관망 행 중 이 팀 것(`watchMeta` 종류: 철수·파트너십 탈락·계약 만료·합류 보도)을 위에 둔다.
- 로스터 인물의 계약 만료(`contractUntil`) 중 만료됨·90일 이내·올해 연도만 있는 것을 "계약 종료 예정" 목록으로 둔다.
- 운영 종료(`active:false`)면 지금 머리 문구를 그대로 쓴다.
- 바꿀 곳: `js/model.js` 에 `teamNews(id, IDX, today)` 순수 함수(시험 대상), `js/views/team.js` 에 묶음 하나, 사전 키 2~3개.
- 계약 데이터가 채워지기 전에는 관망 행만 보인다. 묶음이 비면 그리지 않는다.

### 1.9 로스터 탭 추가 (S + P 선행)

**설계**
- 새 탭 `roster`(#roster), mode `"roster"`. 지역 필터는 쓰고 상태 필터는 쓰지 않는다.
- 대상 팀: `tier` 가 partner·ascended 인 팀(현재 41개). 권역 → 팀 이름 순서다.
- 팀마다 카드 한 장: 팀 링크, 현재 로스터(`teamMoves(id).roster` 를 그대로 사용, 선수 → 코치 순), 이번 시즌 들어온·나간 인원 수.
- 새 파일 `js/views/roster.js` 하나. `buildTabs` 의 탭 목록에 한 줄, `renderView` 에 mode 분기 하나를 추가한다.

**선행 데이터 (P, 중요)**: people.json 에는 소식에 나온 인물만 있다(184명). 그래서 이적이 없던 선수는 로스터에서 빠진다. 1부 41팀 × 약 6명 ≈ 250명의 현재 로스터를 '인물' 탭에 한 번 채우고, 정기 실행에서 유지해야 한다. 채워지기 전에 공개하면 로스터가 비어 보인다. 그래서 다음 순서로 한다.
1. 지시문에 1부 팀 로스터 최초 채우기와 유지 규칙을 넣는다.
2. 사이트는 로스터가 5명 미만인 팀에 "로스터 정보 일부" 표시를 붙여 공개한다.

```text
## Rosters (one-time backfill, then maintain in the 08:50 run)
For every team with tier partner or ascended in the Teams tab, make sure every current player and head coach has a People row
with an open career entry for that team (teamID:YYYY-MM~). Source: Liquipedia team page "Active" roster (tier I).
On each 08:50 run, re-check up to 10 such teams (oldest checked first) and close/open career entries to match.
```

### 1.10 오늘의 소식 탭 추가 (S)

**설계**

- 탭 이름 옆 숫자는 오늘 건수다. 기본 탭은 지금처럼 선수 탭이다(열린 결정 1).

## 3. 열린 결정

1. **오늘의 소식 탭을 기본 탭으로 할지**: 지금 설계는 선수 탭을 그대로 기본으로 둔다.
2. **한국 탭 범위**: 설계는 "한국 국적 또는 한국 팀"이다. 한국 팀의 외국인 선수를 뺄지 정한다.
3. **로스터 탭 공개 시점**: 로스터 채우기가 끝난 뒤 공개할지, "일부" 표시를 달고 먼저 공개할지.
4. **Riot 계약 데이터베이스**: 공개 주소와 예약 작업 환경에서 접근할 수 있는지 사용자가 확인한다. 안 되면 계약은 공식 발표·보도만으로 채운다.
5. **포지션 필터 값**: 시트 포지션 표기가 통일돼 있지 않으면(예: "Flex/IGL") 지시문에 허용 값 목록을 먼저 넣는다.
