# 새 컴퓨터에서 VCT-board 작업 이어가기

현재 컴퓨터(Windows 11)에서 확인한 환경을 기준으로 적었습니다. 위에서 아래로 순서대로 하면 됩니다.

## 0. 옛 컴퓨터에서 먼저 할 일 (가장 중요)

저장소에 올라가지 않은 것은 새 컴퓨터로 오지 않습니다. 현재 `feature/og-en` 브랜치에는 커밋하지 않은 변경이 있습니다.

1. 미커밋 변경을 커밋하고 푸시합니다. 대상은 `index.html`, `privacy/`, `terms/`, `en/privacy/`, `en/terms/`의 수정, `docs/` 아래 새 파일(`인계/`, `지시문/`, `설계/`, `디자인/` 일부)입니다.
2. docx 4개는 `docs/설계/`로 옮겨 둔 상태입니다. 옛 위치의 삭제와 새 위치의 추가를 함께 커밋합니다.
3. `정리후보/`와 `.impeccable/`은 올리지 않아도 됩니다. 다시 만들 수 있거나 도구용 캐시입니다.
4. 푸시 뒤에 `git status`가 깨끗한지, `git log origin/<브랜치>`에 마지막 커밋이 보이는지 확인합니다.
5. 아래 항목은 저장소 밖에 있으므로 필요하면 따로 챙깁니다.
   - Claude Code 세션 기록: `C:\Users\KDB\.claude\projects\C--Users-KDB-Coding\` (선택. 가장 큰 파일이 50MB)
   - Claude 전역 설정: `C:\Users\KDB\.claude\settings.json` (플러그인 목록이 있습니다)
   - 구글 시트와 예약 작업: 아래 6장을 읽고 어디에 있는지 확인합니다.

## 1. 계정과 권한

- GitHub 계정 `4nhackle` 로 로그인해야 합니다. 저장소는 `https://github.com/4nhackle/VCT-board` 입니다.
- 필요한 토큰 권한은 `repo`, `workflow`, `read:org`, `gist` 입니다. 푸시, PR, 병합, 워크플로 조회에 씁니다.
- Claude Code용 Anthropic 계정(또는 사용 중인 로그인)도 필요합니다. 비밀번호와 토큰은 이 문서에 적지 않습니다. 새 컴퓨터에서 직접 로그인하세요.

## 2. 프로그램 설치

현재 컴퓨터의 버전입니다. 같거나 더 높은 버전이면 됩니다.

| 프로그램 | 현재 버전 | 비고 |
|---|---|---|
| Git | 2.56 | |
| Node.js | 24.22 | 배포 서버(CI)는 Node 20을 씁니다. 로컬은 20 이상이면 시험이 돌아가야 합니다. |
| GitHub CLI `gh` | 2.103 | PR 병합과 워크플로 확인에 씁니다. |
| Python | 3.15 | graphify와 일부 문서 추출에 씁니다. |
| Claude Code (데스크톱 앱) | 최신 | |
| Codex CLI | 0.166 | 선택. `npm i -g @openai/codex` |

이 저장소에는 `package.json`이 없습니다. 사이트 빌드와 시험은 Node만으로 돌아갑니다. `npm install`은 필요 없습니다.

## 3. 저장소 받기와 git 설정

```bash
cd C:\Users\<사용자>\Coding
git clone https://github.com/4nhackle/VCT-board.git
cd VCT-board
gh auth login
git config user.name "4nhackle"
git config user.email "347648258+4nhackle@users.noreply.github.com"
```

git 사용자 정보는 이 저장소에만 설정합니다(local config). 기존 커밋과 작성자를 맞추기 위함입니다.

작업하던 브랜치를 이어 받으려면 다음을 씁니다.

```bash
git fetch --all
git switch feature/og-en
```

## 4. 동작 확인

```bash
node scripts/test.mjs
node scripts/validate.mjs
node scripts/css-check.mjs
node scripts/build.mjs _site
node scripts/dev-server.mjs 8080
```

- 시험은 "단위 시험 116개 통과", validate는 "오류 0"이 나와야 합니다(2026-11-05 기준).
- 사이트는 `http://localhost:8080/VCT-board/` 에서 봅니다. 주소 끝의 `/VCT-board/` 가 필요합니다.
- `index.html`을 파일로 직접 열면 데이터를 못 읽어 빈 화면이 나옵니다. 반드시 dev-server로 엽니다.
- 컴포넌트 견본은 `http://localhost:8080/VCT-board/dev/styleguide.html` 입니다.

## 5. 선택 도구 (필요할 때만)

- 화면 스냅숏 비교(`scripts/style-snapshot.mjs`)와 영문 미리보기 이미지 제작은 Playwright가 필요합니다.
  ```bash
  npm i -D playwright
  npx playwright install chromium
  ```
  `-D`로 설치하면 `package.json`과 `node_modules`가 생깁니다. 커밋하지 마세요.
- graphify(코드 지식 그래프): `pip install graphifyy`. 결과 폴더 `graphify-out/`은 저장소에 올리지 않습니다.
- Windows 글꼴: 영문 미리보기 그림은 Segoe UI 굵게로 만들었습니다. 같은 모양이 필요하면 Windows에서 다시 만드세요.

## 6. 저장소 밖에 있는 것 (새 컴퓨터에서 반드시 확인)

1. **GitHub Pages 설정.** 서버 쪽 설정이라 새 컴퓨터에서 할 일은 없습니다. 다만 Source가 `GitHub Actions` 인지 한 번 확인합니다(저장소 Settings → Pages). 배포 워크플로는 `.github/workflows/pages.yml` 입니다.
2. **데이터를 채우는 예약 작업과 구글 시트.** `main`에는 `시트 반영 YYYY-MM-DD HH:MM (KST)` 커밋이 자동으로 쌓입니다. 실행 시각은 08:50, 09:35 KST이고, 11월 16일까지는 14:50, 15:35, 20:50, 21:35 KST도 있습니다. 이 작업이 어디에서 돌아가는지(Claude 예약 작업인지, 클라우드 루틴인지, 현재 컴퓨터의 작업 스케줄러인지)는 이번 점검에서 확인하지 못했습니다. 현재 컴퓨터에서 도는 것이라면 새 컴퓨터로 옮기거나 다시 만들어야 합니다. 옮기기 전에 옛 컴퓨터에서 먼저 확인하세요. 시트 주소와 지시문은 `docs/설계/VCT-board_예약작업_변경설계서.docx` 를 봅니다.
3. **구글 검색 소유권 파일.** `google41eb36b5d21a9bad.html` 은 저장소에 있으므로 따로 할 일이 없습니다.
4. **Claude 플러그인.** 현재 `settings.json`에 켜져 있는 것은 `superpowers`, `agent-skills`, `ecc`, `ponytail`, `caveman`, `codex`, `ui-ux-pro-max`, `andrej-karpathy-skills` 입니다. 새 컴퓨터에서 같은 환경을 원하면 `settings.json`을 복사하거나, Claude Code에서 플러그인 마켓플레이스로 같은 것을 설치합니다. 저장소 작업 자체에는 필수가 아닙니다.
5. **Claude 전역 규칙.** `C:\Users\KDB\.claude\CLAUDE.md` 에는 `/graphify` 호출 규칙이 있습니다. graphify를 쓸 때만 필요합니다.

## 7. Claude Code로 이어서 작업하기

1. Claude Code 데스크톱 앱에서 작업 폴더를 `VCT-board` 로 엽니다.
2. 첫 요청으로 이렇게 말합니다: `docs/README.md 와 docs/인계/세션-인계.md 를 읽고 현재 상태를 요약해줘`
3. 이전 세션 기록을 옮겼다면 폴더 이름이 경로 기준이라 새 경로에 맞게 이름이 바뀌어야 보입니다. 옮기지 않아도 `docs/PROGRESS.md` 에 회차별 기록이 모두 있으므로 이어 가는 데 문제는 없습니다.

## 8. 작업 규칙 (현재 방식 그대로)

- 회차 지시문(`docs/지시문/구현-회차별/…N회차…md`)을 첨부해 한 회차씩 진행합니다. 다음 번호는 19회차입니다.
- 회차마다 브랜치를 만들고, 시험과 validate를 통과시키고, `docs/PROGRESS.md` 에 결정과 확인 결과를 적고, PR을 엽니다.
- 병합과 푸시는 사용자가 말했을 때만 합니다. 지시문에 "병합하지 않는다"가 있으면 하지 않습니다.
- 병합 시각은 예약 작업 실행 시각의 앞뒤 30분을 피합니다(위 6장 시각 참고).
- 병합 뒤에는 배포 성공을 확인합니다.
  ```bash
  gh run list --branch main --workflow pages.yml
  ```
- 응답은 한국어로 받습니다.
