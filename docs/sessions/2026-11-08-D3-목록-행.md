## 바꾼 파일

- `js/components/row.js`: 기본 행의 구조를 바꿨다. 칸은 `.main`(이름·메타), `.move`(경로 또는 팀, 팀별 보기에서는 `→ 도착` 또는 `—`), `.state`(알약·배지·상태 글 `.lead`), `.when`(날짜), 펼침 단추 `.row-x`, 펼침 영역 `.row-fold`(설명·단체 링크·출처 줄). 단추의 `aria-controls` 와 영역 `id` 가 같다(`row-fold-N`). 목록마다 `colsHTML()` 을 더했다. 지켜볼 팀 행(`watchHTML`)은 그대로다. 지역 짧은 이름은 메타 줄 앞에 붙인다(최근 소식 보기). 팀 로고 자리(D4)는 주석으로만 표시했다.
- `js/views/regions.js`, `js/views/recent.js`: 목록 시작에 `colsHTML()` 을 넣었다. 두 파일의 import 를 바꿨다.
- `js/main.js`: `renderView` 가 `resetFolds()` 로 펼침 번호를 되돌린다. 문서 클릭 처리기에 행 펼침(`toggleRow`)을 더했다. 단추나 행의 빈 곳을 누르면 여닫는다. 링크·단추·펼침 영역 안의 클릭은 제외한다. 다시 그리지 않는다(영역의 `hidden` 과 단추의 `aria-expanded`·`aria-label` 만 바꾼다).
- `css/style.css`: `.list` 에 칸 너비 토큰(`--col-*`), `.row` 를 다섯 칸 격자로(데스크톱), `.cols`(머리 행, 데스크톱에서만), `.move`·`.when`·`.lead`·`.row-x`·`.row-fold` 규칙. 모바일은 `grid-template-areas` 로 두 줄 요약(첫 줄 이름·상태, 둘째 줄 이동, 셋째 줄 날짜·단추). 지켜볼 팀 행은 옛 두 열 격자와 모바일 세로 쌓기를 유지한다.
- `js/i18n/ko.js`, `js/i18n/en.js`: `row.expand`, `row.collapse`, `col.person`, `col.move`, `col.status`, `col.date`.
- `scripts/test.mjs`: `resetFolds` 를 import 하고, 같은 내용을 비교하는 기존 시험(계약 칸, caption)에서 비교 전에 번호를 되돌린다. 새 시험 3개: 단추와 영역 id, 상태 글 위치, 출처 링크 위치, 지역 짧은 이름, `—`, 머리 행의 `aria-hidden`.
- `docs/PROGRESS.md`: 한 절.

## 결정과 이유

- 목록 줄을 `<table>` 로 바꾸지 않았다(지시문). `.rh` 머리와 점프 상자, 고정 위치가 목록 사이의 머리에 기대기 때문이다.
- 칸 너비를 `.list` 에 토큰으로 두었다. 목록마다 같은 값이라 목록끼리 칸이 맞는다. 측정: 1280px 에서 여러 목록의 첫 칸 왼쪽 끝이 모두 113px.
- 상태 글(`lead`)은 알약 아래 작은 글로 펼침 밖에 둔다(지시문). 예전에는 본문 앞머리였다. 이동 행과 "팀 이탈"·"계약 완료"·"방출"·"이탈 보도" 로 시작하는 행은 예전과 같이 상태 글을 쓰지 않는다.
- 계약 글은 메타 줄에 그대로 둔다. 기존 시험이 메타 줄 끝의 "계약 ~…" 을 확인한다. 지시문은 펼침에 계약 글을 두라고 했지만, 시험과 맞추려고 메타 줄에 남겼다.
- 펼침 단추는 설명·출처 영역이 있는 행에만 둔다. 없으면 단추도 없다.
- 펼침 번호를 `renderView` 에서 되돌린다. 목록을 다시 그릴 때마다 번호가 처음부터 다시 셈되므로 한 화면 안에서 `id` 가 겹치지 않는다.
- 펼침 상태는 주소·저장소에 남기지 않는다(지시문). 다시 그리면 접힌다.
- 모바일 두 줄은 지시문의 "from → to · position · date · status text" 한 줄 대신, 이동은 둘째 줄, 날짜와 단추는 셋째 줄에 둔다. 한 줄에 다 넣으면 375px 에서 넘쳐서다.
