# PR 22 로스터 탭 검색 되살리기 (2026-11-09)

## 목적
지시문 `docs/instructions/PR22-roster-search.md` 대로 로스터 탭의 검색 칸(`#q`)이 동작하게 한다. 이전에는 `rosterHTML` 이 `state.q` 를 읽지 않아 입력해도 바뀌지 않았다. 데이터는 바꾸지 않는다.

## 기준
- 기준: `origin/main` 0ae65f9 (지시문의 기준 0ae65f9 와 같다. PR 19–21 병합 뒤, 시트 반영 커밋 포함).
- 작업 자리: 이 체크아웃, 브랜치 `feat/roster-search`. 커밋하지 않았다.
- PR 21 지시문 업로드는 이미 반영되어 있다(PR #54 병합, `3e5db2c`). 다시 하지 않았다.

## 바꾼 파일
- `js/views/roster.js`:
  - `searchCard(c, q)` 를 새로 두었다. 팀 이름·짧은 이름·ID 가 맞으면 원래 카드를 그대로 쓴다(로스터 전체). 아니면 이름·실명·역할이 맞는 인물만 남긴 복사본을 만든다(`Object.assign`). 맞는 인물이 없으면 카드를 뺀다. `inCount`·`outCount`·`partial` 은 팀 기준이라 그대로 둔다.
  - `rosterHTML` 은 지역 거르기 다음에 `state.q`(trim, 소문자)를 적용한다. 비면 거르지 않는다. 지역 머리 개수(`count.teams`)와 바로가기 상자는 거른 카드로 그려진다.
- `scripts/test.mjs`: `rosterHTML 검색` 시험을 하나 추가했다. 팀 이름이면 팀 전체, 인원 수는 팀 기준, 인물 이름은 그 인물만, 실명도 찾음, 대소문자 무관, 없으면 `class="empty"`, 지역 머리 개수는 거른 기준, 빈 검색은 거르지 않음.
- `docs/instructions/PR22-roster-search.md`: 업로드된 지시문을 저장소 지시문 폴더에 복사했다(PR 19–21 파일과 같이 커밋하지 않은 상태).

## 결정과 이유
- `main.js` 는 바꾸지 않았다. 검색 입력은 이미 `state.q` 를 `renderView` 로 다시 그린다. 로스터 분기가 `state` 를 넘기지 않던 것이 원인이었다(이제는 `rosterHTML` 이 읽는다).
- 인물 검색에서 역할(`role`)도 본다. 지시문이 정한 대로다.

## 확인 결과 (직접 실행)
- `node scripts/test.mjs`: 단위 시험 162개 통과(161 → 162).
- `node scripts/validate.mjs`: 오류 0, 경고 648. 이전 640 에서 늘었다. 원인은 `origin/main` 의 시트 반영 커밋(0ae65f9)이 데이터를 바꾼 것이고, 이 변경과는 무관하다.
- `node scripts/build.mjs _site`: 빌드 완료(인물 331쪽, 팀 350쪽 각각 한·영).
- 내장 브라우저, 정적 서버 `_site`, 1024 폭, `#roster`:
  - 기본: 지역 머리 4, 팀 머리 34, 명단 행 135.
  - 팀 이름 `100 Thieves`: 지역 머리 1, 팀 머리 1, 행 6(팀 전체).
  - 없는 검색어: 빈 문구(`class="empty"`), 지역·팀·행 0.
  - 빈 칸으로 지우면 기본으로 돌아온다(행 135).
  - 선수 이름 `Asuna`: 행 1. 대문자 `ASUNA` 도 같은 결과.
  - 지역 칩과 결합: EMEA 에 `100 Thieves` → 0(팀이 AMER), AMER 에 `100 Thieves` → 행 6. 지우고 ALL 로 돌리면 4개 지역 머리 복귀.
  - 바로가기 상자는 거른 지역 머리만 담는다(검색 결과 1지역이면 상자 자체가 숨는다, 기존 규칙).
