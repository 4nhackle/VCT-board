# 디자인 브리프 — 이적 원장(Transfer Ledger)

**한 줄 요약:** 통신사 속보판처럼 빠르게 훑고, 장부처럼 출처를 따라가는 정보 보드다. 장식보다 위계와 출처 신뢰감을 앞세운다.

## 누가, 어떤 상황에서
- **e스포츠 팬:** 출퇴근길 모바일에서 새 소식을 훑는다. 이름, 상태, 날짜만 보고 넘긴다.
- **기자·분석가:** 데스크톱에서 출처, 보도 시각, 교차 확인 여부를 확인한다.

## 분위기와 이유
- 종이빛 바탕과 짙은 잉크를 쓴다. 강조색은 기존 초록 하나뿐이다. 초록은 파비콘·og 이미지와 이어지는 사이트의 정체성이라 유지한다.
- 개성은 세 가지로 낸다.
  - 굵기 차이가 큰 타이포: 이름 700, 구역 머리 800.
  - 상태 띠와 기호: ○ ✓ → ?.
  - 상세 화면의 모노그램: 이름 첫 두 글자를 CSS로 그린 것.
- 본문에는 읽히는 문장만 남긴다. 출처·시각·교차 확인 같은 원자료는 그 아래 작은 "출처 줄"로 내린다.

## 토큰(`css/style.css`, 3층)
토큰은 세 층이다. 규칙은 2층과 3층만 쓴다. 1층(`:root`와 다크 블록)의 기본값을 규칙이 직접 쓰면 `scripts/css-check.mjs` 가 실패한다.

**1층 기본값** (`:root`, 다크는 `prefers-color-scheme` 블록과 `data-theme="dark"` 블록이 같은 값을 다시 쓴다)
| 이름 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--fs-1`…`--fs-6` | 13·14·15·17·22·28px | 같음 | 글자 크기 단계 |
| `--fs-team`, `--fs-region`, `--fs-site`, `--fs-hero` | 19, 22(모바일 18, 20), 19, 24 | 같음 | 팀 머리, 지역 머리, 모바일 제목, 모바일 상세 이름 |
| `--sp-1`…`--sp-7` | 4·8·12·16·24·32·48px | 같음 | 간격 단계 |
| `--r-1`, `--r-2`, `--r-pill` | 4, 8, 999px | 같음 | 모서리 |
| `--tap` | 36px(모바일 44px) | 같음 | 터치 높이 |
| `--neutral-0/50/200/600/900`, `--neutral-float`, `--neutral-mono(-fg)` | 흰색·#F7F6F2·#DEDAD1·#575D66·#16181D… | 1A1E1C·111413·2E3531·A3ABA6·E9ECEA… | 바탕과 글자 원색 |
| `--green-*`, `--amber-*`, `--slate-*`, `--red-*` | 초록·호박·회색 파랑·붉은색 원색 | 밝은 색으로 바뀐 원색 | 강조와 상태 원색 |
| `--shadow-float-prim` | `0 2px 8px rgba(22,24,29,.14)` | none | 떠 있는 막대 그림자 |

**2층 의미** (`:root`에서 한 번만 정의한다. 값은 1층을 가리키므로 다크 모드는 1층만 바뀐다)
| 이름 | 용도 |
|---|---|
| `--text-meta`(13), `--text-small`(14), `--text-body`(15), `--text-name`(17) | 메타·칩·본문·이름 글자 |
| `--text-region`, `--text-team`, `--text-title`(22), `--text-display`(28), `--text-site`, `--text-hero` | 지역 머리, 팀 머리, 사이트 제목, 상세 이름, 모바일 제목·상세 이름 |
| `--space-xs`(4) · `--space-s`(8) · `--space-m`(12) · `--space-l`(16) · `--space-xl`(24) · `--space-2xl`(32) · `--space-3xl`(48) | 간격. 역할 이름 대신 단계 이름을 쓴다(한 단계 값이 여러 역할에 쓰여서) |
| `--radius-s` · `--radius-m` · `--radius-pill` | 모서리 |
| `--control-h` | 터치 높이(= `--tap`) |
| `--color-bg`, `--surface`, `--surface-float`, `--color-ink`, `--color-mute`, `--color-line`, `--color-line-strong`, `--color-accent`, `--color-on-accent`, `--color-mono-bg`, `--color-mono-fg` | 바탕, 면, 글자, 선, 강조 |
| `--status-{open,signed,left,warn}-{bg,fg,rail}` | 상태 칸(구직 중 호박, 합류 초록, 이탈 회색, 경고 붉은색) |
| `--shadow-float`, `--link-underline-offset`(3px) | 떠 있는 면 그림자, 밑줄 위치 |
| `--tab-h`, `--tabs-h`, `--dock-h`, `--dock-bottom`, `--dock-right`, `--wrap`, `--font`, `--mono` | 고정 요소와 레이아웃(16진 색 아님) |

**3층 컴포넌트**: 규칙 맨 위에 `--이름: 값`으로 선언한다(예: `.pill { --pill-gap: 5px; }`, `.row { --rail-w: 3px; }`). 날것의 px 는 여기서만 쓴다. 테두리·윤곽선 두께(1~3px)는 예외다.

**예외**: `0`, 테두리·윤곽선 두께 1~3px, `100%`, `auto`, `none`, `inherit`, `currentColor`, `transparent`.

**글꼴**: 웹폰트 없음. `Pretendard` → `Apple SD Gothic Neo` → `Malgun Gothic` → `Noto Sans KR` → `system-ui`. 날짜·시각은 `ui-monospace` + `tabular-nums`.

**새 스타일을 넣을 때**
1. 2층 의미 토큰이 있으면 쓴다.
2. 없으면 2층에 의미 토큰을 먼저 만든다. 값은 1층 값을 가리킨다.
3. 규칙에 특정 크기가 꼭 필요하면 3층 컴포넌트 토큰으로 그 규칙 맨 위에 선언한다.
4. 견본 페이지(`dev/styleguide.html`)에 예를 추가한다.
5. `node scripts/css-check.mjs` 를 통과시킨다. 중복 선택자를 만들지 않는다.

**외부 디자인 시스템을 쓰지 않는 이유**: 이 사이트는 의존성이 없는 순수 JS와 정적 빌드다. 300KB 예산을 두고 있고, 시험과 빌드가 Node 만으로 돈다. Astryx 같은 React·StyleX 체계는 이 구조에 맞지 않고, 한글 타이포그래피 제어도 직접 해야 한다. 그래서 토큰 층과 견본, 자동 점검만 들였다.

## 핵심 컴포넌트 규칙
- **필터:** 두 줄이다.
  - 1줄: 상태 칩(개수 포함)과 테두리 있는 검색란.
  - 2줄: 지역 칩과 정렬 칩. 새 소식 수는 "최근 소식순" 칩 안의 배지로 둔다.
  - 모바일에서는 검색란이 맨 위에 오고, 칩 줄은 한 줄 가로 스크롤이다.
  - 모바일 2줄(15회차 U-4): 지역 칩은 첫 줄에서 한 줄 가로 스크롤(화면 끝까지 bleed)이고, 정렬 칩은 그 아래 줄에서 넘치면 줄을 바꾼다. 왼쪽 끝은 본문 왼쪽 선과 같다. 칩 "새 N" 배지는 잘리지 않는다.
- **탭:** 화면 위에 붙는다(sticky). 지역·날짜 머리는 탭 바로 아래에 붙는다.
- **문구는 `t()`로만 쓴다(10회차).** 화면 글자는 `js/i18n/ko.js`·`en.js` 사전에 둔다. 한국어 상태 글을 읽는 정규식(`pillOf`, `watchMeta`, `routeOf` 등)은 데이터 판정용이라 번역하지 않고, 옆에 `데이터 판정용` 주석을 단다.
- **머리말(12회차 B-2):** 601px 이상은 왼쪽 칸에 제목·문장, 오른쪽 칸에 위에서부터 EN/KR 전환과 후원 메뉴(601px 이상: 두 요소 모두 오른쪽 끝 정렬, 사이 간격 `--space-m`. 17회차에서 `align-self: center` 를 없애 가운데로 밀리던 문제를 고쳤다). 600px 이하는 한 칸으로 제목, 문장 순서이고, 그 아래 한 줄에 후원 메뉴(왼쪽)와 EN/KR(오른쪽), 좁으면 줄을 바꾼다. 후원 링크는 항상 보이고, 펼침 상자로 숨기지 않는다
- **팀 머리:** 인원이 한 명이어도 "팀명 n명" 으로 같은 모양이다. 15회차 U-1: 팀 머리 위에 `--line-strong` 구분선(지역 머리 바로 다음 첫 팀은 없음), 위 여백 `--sp-5`, 아래 `--sp-2`. 모바일에서는 긴 팀명이 줄을 바꾸고 인원 수는 줄 끝에 온다.
- **행:**
  - 위 줄: 왼쪽 3px 상태 띠 | 이름(17/700)과 메타(역할·국적) | 상태 알약·날짜(모노).
  - 그 아래 본문, 맨 아래 출처 줄.
  - 이동은 `출발 → 도착` 경로 줄로 보여 준다. 알약은 단계만 말한다(`✓ 합류 확정`, `◇ 합류 보도`).
- **상태 알약:** 색, 기호, 말을 함께 쓴다. 구직 중 ○, 합류 ✓, 떠남 →, 확인 필요 ?(점선).
  - 합류 보도(미확정)는 ◇ 와 점선 테두리, 중립색으로 쓴다(예: `◇ 합류 보도`). 초록 ✓ 은 공식 확정에만 쓴다.
- **출처 줄:** `출처이름 · 시각(KST)`, `교차 확인 A, B`, 출처 링크를 둔다. 규칙에 맞지 않는 글은 본문에 원문 그대로 남긴다.
- **지켜볼 팀:**
  - 왼쪽: 종류 배지(철수·해체 / 파트너십 탈락 / 계약 만료 / 합류 보도)와 팀 링크.
  - 오른쪽: `확정` 도장과 `확인 M/D`.
  - "대상" 은 라벨로 본문과 구분한다.
- **상세:**
  - 사이트 제목은 작은 줄로 줄이고, `<h1>` 은 이름 하나만 둔다.
  - 머리는 모노그램 + 이름 + 상태다. 그 아래에 사람마다 같은 칸 수의 정보 표를 둔다.
  - 빈 값은 "미공개" 를 흐리게 쓴다.
  - 경력의 진행 중 칸은 면 배경, 진한 점, "진행 중" 라벨로 구분한다.
- **긴 목록:**
  - `content-visibility: auto` 는 검토 후 쓰지 않는다. 화면 밖 목록의 높이가 추정값이 되어, 뒤로 가기 스크롤 복원과 바로가기 위치가 어긋나기 때문이다.
  - 한 화면 넘게 내리면 오른쪽 아래에 막대가 나온다: "바로가기"(지역·날짜 고르기) + "맨 위로".
- **떠 있는 컨트롤(막대):**
  - 테두리는 `--line-strong`(= 글자색 `--mute`), 면은 `--float`, 높이는 `--dock-h`로 다른 컨트롤과 맞춘다.
  - 그림자는 라이트에서만 쓴다. 다크 바탕에서는 검은 그림자가 보이지 않으므로, 다크는 그림자 대신 면을 살짝 밝게 한다.
  - 화살표는 인라인 SVG(`currentColor`, `aria-hidden`)나 토큰 색 테두리로 그린다. 글자("↑")는 쓰지 않는다.
  - 고르기 상자의 OS 화살표는 `appearance: none` 으로 끄고 토큰 색 화살표로 바꾼다.
- **고정 머리와 바로가기:** 구역 머리는 `--tabs-h` 에 붙는다. 탭과 머리 사이에 틈이 생기면 행 글자가 비쳐 보이므로 틈을 두지 않는다.
- **푸터 여백:** 맨 아래 여백은 막대 높이와 위치를 더해 계산한다. 마지막 줄이 막대 밑에 깔리지 않게 하기 위해서다.

- **EN/KR 전환(11회차, 12회차 B-2 배치):** 머리말 오른쪽 칸 위(601px 이상) 또는 600px 이하의 후원 메뉴 오른쪽. 두 칸짜리 캡슐(`--r-pill`, 높이 `--tap`, 테두리 `--line-strong`). 현재 언어는 굵기와 밑줄로 보인다(색만으로 구분하지 않는다). 375px 에서도 가로 넘침이 없어야 한다.
- **KR 표시(11회차):** 영문 화면에 한국어 데이터 글을 그대로 보일 때는 `<span lang="ko" class="kr-src">` 로 감싸고 뒤에 `KR` 칸(`.kr-tag`: 글자 `--mute`, 테두리 `--line`, 모서리 `--r-1`)을 붙인다. 상태·역할은 용어집으로 옮겨지면 영문으로, 못 옮기면 원문 + KR 로 보인다. 사람 이름은 `lang="ko"` 만 붙이고 KR 칸은 붙이지 않는다.
- **영문 화면의 한글은 `lang="ko"` 안에만.** 보이는 글과 `aria-label`·`placeholder`·`title` 에서 한글이 `lang="ko"` 밖에 있으면 안 된다(11회차 검사로 확인).

- **영문 화면 후원은 Ko-fi만(13회차 E-1):** 카카오페이는 국내 계좌 송금이라 영문 화면의 머리·푸터·약관·개인정보에서 숨긴다. 영문 약관·개인정보에는 링크 없이 "Korean domestic transfer, Korean page only"라고만 적는다. 한국어 화면은 그대로다.
- **목록 칸은 인물 정보로 보충(14회차 A-1):** 목록 행의 포지션(코치는 역할)·국적이 비면 인물 정보(people)의 값을 쓴다. 행에 값이 있으면 행 값을 쓴다. `-` 는 빈 칸이다.
- **생년월일 공개 규칙(14회차 A-2):** 칸 이름은 "생년월일"(Born). 날짜가 있으면 날짜와 나이, 연도만 있으면 "연도 (약 N세)". 만 18세 미만은 날짜를 숨기고 연도만 보인다. 없으면 "미공개".

- **후원 문구(15회차 U-2):** 후원 메뉴 머리 글자는 한국어 "개발자 커피 사주기", 영문 "Buy the developer a coffee"다. 링크의 `aria-label`("Ko-fi로 후원" 등)은 그대로다. 모바일에서 라벨은 칩 위 줄로 갈 수 있지만 칩 사이에 끼지 않는다.
- **EN/KR 전환 폭(15회차 U-3):** `.lang-switch` 는 내용 폭을 지킨다(`flex: 0 0 auto`, `max-content`). 부모 flex 가 늘이지 않는다.
- **공유 이미지는 언어별(18회차):** 한국어 페이지는 `og.png`, 영문 페이지는 `og-en.png` 을 쓴다. 글자는 사전 문구와 같게 한다.

## 쓰지 않기로 한 대안
- **e스포츠 방송풍(다크 네온, 빨강 강조):** 긴 글 읽기를 방해한다. Riot 브랜드를 흉내 내는 것처럼 보일 위험도 있다.
- **카드 그리드 대시보드:** 화면당 정보량이 줄어 모바일에서 훑는 속도가 떨어진다.
- **표(table) 레이아웃:** 모바일에서 가로 스크롤이 생긴다.
- **웹폰트 직접 배포(Pretendard 등):** 한글 2,350자를 한 굵기로만 넣어도 약 300KB라 예산(300KB)을 넘는다. 시스템 한글 글꼴로도 충분히 읽기 좋고, 첫 표시가 가장 빠르다.
