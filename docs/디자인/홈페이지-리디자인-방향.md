# 홈페이지 리디자인 기획 및 구현 지시서

## 목표와 원칙

오늘의 이적 소식과 선수·팀 정보를 빠르게 훑고, 필요한 항목은 필터와 권역·팀 탐색으로 찾을 수 있게 한다. 출처, 갱신 시각, 정보의 확정 여부를 분명히 표시한다.

핵심 원칙:

- 첫 화면에서 최신 소식과 로스터 현황을 빠르게 파악한다.
- 탐색은 상위 탭, 권역 탭, 필터 순으로 단순하게 구성한다.
- 짧은 목록 요약과 상세 정보를 구분한다.
- 확인되지 않은 데이터는 추측해 채우지 않고 `미공개` 또는 `확인 중`으로 표시한다.
- 기존 정적 사이트 구조와 디자인 토큰을 우선 재사용한다.

## 상단 메뉴

## 1. 오늘의 소식

- 최근 24시간 안에 발생한 소식을 보여준다.
- 최신 시간순으로 정렬한다.
- 권역별 탭을 제공한다.
- 각 항목은 핵심 변화와 출처를 빠르게 확인할 수 있게 요약한다.

## 2. 이적 & LFT

이적과 LFT를 하위 탭으로 나눈다.

### 이적

- 선수와 코치를 구분한다.
- 팀, 권역, 국적 필터를 제공한다.
- 시간순 또는 팀순으로 정렬한다.
- 팀순은 권역별로 묶은 뒤 팀 이름 알파벳순으로 정렬한다.
- 선수 이름 옆에 국적 이모지를 표시한다.
- 항목 순서: 날짜 → 선수 → From → To → 출처

### LFT

- VCT와 non-VCT를 구분한다.
- 선수와 코치를 구분한다.
- 권역별 탭을 제공한다.
- 항목 순서: 날짜 → 선수 이름 → 지역 → 역할 → 기존 소속팀 → 출처

### 필터·정렬 동작

- 이적의 필터는 선수/코치, 팀, 권역, 국적 기준으로 조합할 수 있다.
- 정렬은 시간순과 팀순을 제공한다. 팀순은 권역 순서를 고정하고, 각 권역 안에서 팀 이름 알파벳순으로 정렬한다.
- 필터 결과 건수와 필터 초기화 동작을 제공한다.
- 필터가 좁은 화면을 가리지 않도록 접을 수 있는 패널 또는 가로 스크롤 칩으로 표시한다.

## 3. 로스터

- 권역별 탭으로 팀을 탐색한다.
- 팀 로고를 누르면 해당 팀의 로스터를 표시한다.
- 팀별로 선수 최대 6명, 스태프 최대 3명, 링크 최대 5개를 표시한다.
- 로고가 없거나 표시되지 않을 때는 팀 약칭으로 대체한다.
- 팀 상세는 선수, 스태프, 관련 링크를 구분해 표시한다.
- 선수·스태프 수는 최대 표시 개수이며, 실제 데이터가 적으면 존재하는 항목만 표시한다.

## 4. 선수 상세 정보

- 기존 선수 상세 페이지에 생년월일과 계약 만료 정보를 보충한다.
- 보유할 수 있는 항목: 생년월일, 나이(계산 가능한 경우), 현재 팀, 역할, 국적, 계약 만료일 또는 계약 상태, 경력, 출처.
- 계약 만료일과 계약 만료 여부는 구분한다. 날짜가 확인되지 않으면 임의로 만료 여부를 판정하지 않는다.
- 각 정보의 출처를 필드 또는 관련 묶음에 연결한다. 출처가 없는 값은 확정 정보처럼 표시하지 않는다.
- 생년월일은 공개 자료에서 확인 가능한 경우에만 입력하고, 미성년자 등 공개에 주의가 필요한 경우 기존 공개 정책을 따른다.

## 5. 반응형 레이아웃

- 모바일, iPad 세로·가로, 4:3 화면, 데스크톱에서 읽기 쉽게 조정한다.
- 화면 폭에 따라 목록의 밀도와 배치를 바꾼다.
- 터치 기기에서는 탭과 필터를 누르기 쉽게 배치한다.
- 핵심 정보를 보기 위해 가로 스크롤이 필요하지 않게 한다.
- 특히 4:3 iPad 세로·가로 화면에서 필터, 탭, 팀 목록이 겹치거나 과도하게 좁아지지 않게 한다.
- 팀 로고 선택과 탭 조작은 터치 입력에 맞는 크기와 간격을 둔다.

## 시각 디자인 원칙

- 팀 로고와 권역 탭으로 로스터를 빠르게 찾게 한다.
- 정보 위계를 분명히 하고, 색은 권역과 상태를 구분하는 데 사용한다.
- 확정·보도·미확정 상태는 색뿐 아니라 텍스트로도 구분한다.
- 출처와 기준 시각은 목록에서 찾기 쉽게 유지한다.
- 데스크톱의 정보량을 모바일 화면에 그대로 압축하지 않는다.
- 색상은 권역·상태·선택 상태를 구분하는 데 사용하고, 텍스트 라벨과 함께 제공한다.
- 로고와 국적 이모지는 인식 보조 수단으로 사용하며, 핵심 정보를 대체하지 않는다.

현재 크롤링 범위가 너무 좁다는 문제를 해결한다.

- 구단 공식 SNS( X, Instagram, Youtube), Sheep esports( X, Instagram, 홈페이지), vlr.gg, Liqipedia

## 제작 및 검수

1. **기획·설계 및 지시문 작성 — Opus**
   - 요구사항, 화면 구조, 데이터 필드, 상태 표현, 반응형 동작을 확정한다.
   - 구현 범위와 완료 조건을 작업 지시문에 명시한다.
2. **코드 구현 — Haiku High**
   - 승인된 지시문에 따라 작은 단위로 구현한다.
3. **검사 — Luna Extra high**
   - 기능, 출처·상태 표현, 크롤링 결과, 접근성, 반응형 화면을 점검한다.
   - 오류와 누락을 수정한 뒤 완료 여부를 보고한다.
4. **홍보글 작성 — ChatGPT**
   - 플랫폼별 문구와 링크를 준비한다: Reddit, VLR.gg, valorant_penguin, 디시.
   - 게시글은 실제 구현·검수 결과만 반영하며, 게시 전 사용자가 확인한다.

이 순서는 작업자/모델 배정안이다. 각 단계의 입력물과 완료 조건을 먼저 정하고, 도구 배정이 달라져도 같은 산출물을 검토할 수 있게 한다.

## 구현 전 확인할 항목

- 국적 이모지의 표시 방식과 이름 데이터 기준
- 팀 로고 출처와 누락 로고 대체 처리
- 링크 최대 5개의 범위와 표시 우선순위
- 24시간 소식의 시간대 기준
- 모바일·iPad·4:3 화면에서 탭과 필터가 동작하는 방식
- 계약 만료일·생년월일에 사용할 허용 출처와 데이터 공개 기준
- 크롤링 대상, 요청 주기, 중복 판정 기준, 수동 검토 절차
- 선수 6명·스태프 3명·링크 5개의 최대 표시 규칙과 초과 데이터 처리
- 각 구현·검수 단계의 입력물, 완료 조건, 담당 도구
